# 班底页面低保真线框图

> 文档版本：v1.8-draft
> 更新日期：2026-08-31
> 状态：配置闭环与桌面 Shell 线框收敛稿
> 关联文档：[《产品与页面架构》](./产品与页面架构.md)

## 1. 本轮收敛目标

v1.4-draft 将 Bandi Desktop 收敛为 Claude Code 多 Agent 配置管理平面：

- 一级导航固定为：概览、Agents、组织、Workspaces、资产；设置沉底；
- Workflow / SOP 作为资产与 Agent 配置模块存在，不设一级“工作流”；
- 删除一级“运行”，不新增“候选”或“发布中心”；
- 首次安装优先导入已有 Claude Agent 或创建个人 Agent；Workspace、Plugin 与 Company 均按需增加；
- Agent 详情升级为完整配置核心页，AgentPackage 完整目录树、文件预览/源码、配置编辑、保存和历史在同一上下文完成；
- Skill 本体在资产中管理来源和版本生命周期，Agent Skills 只管理显式引用；
- 配置概览完成首次引导后关注最近保存版本、配置缺失、外部变化、配置文件冲突、待审核正式记忆候选和快捷入口，不承担运行监控；
- 存储位置、外部变化保护和备份恢复收敛到“设置 → 配置与备份”单屏，不新增全局一级菜单；
- Desktop 所有页面只管理多 Agent 的组织关系与配置资产，不创建、接收或处理任务；
- 任务目标、方案确认、部门/员工分配、执行、阻塞、审批、汇报和验收，全部在用户自己的 Claude Code 中由董事长助理协同完成；
- 用户无需在 Desktop 为每次任务选择部门或员工，董事长助理和部门主管依据已保存配置在终端分层委派；
- Claude Code 保留全部任务交互与执行中间状态，Desktop 不镜像聊天、工具调用、Todo、日志或 Agent View；
- 来源与有效配置只在排错、追溯和冲突处理时按需展开，不占据默认主流程；
- SOP 页面只编辑定义，不运行 SOP；正式记忆审核是唯一审核例外；长期权限扩大、恢复、删除和共享影响都称为当前操作的风险确认。

本轮不锁定最终颜色、字体、图标、圆角和字段级交互。

## 2. 线框约定与产品边界

- `[按钮]`：操作；
- `(状态)`：只读状态；
- `▼`：切换或展开；
- `⋯`：更多操作；
- `!`：异常、限制或需确认；
- `● / ○`：选择；
- 路径、命令、版本和哈希在正式 UI 中使用等宽字体；
- “保存”表示将变更写入明确展示的配置文件，不引入独立草稿/发布中心；
- “正式记忆候选”仅指拟写入长期正式 MemorySpace 的候选，不包括 Todo、聊天摘要、工具结果、过程日志或临时上下文；
- 页面数据来源证据标注为 `real`（真实读取或写后验证）、`memory-only`（当前页面内存）、`demo-fixture`（预置演示）或 `read-only`（有来源但当前不可写）；系统能力状态另行使用 `supported`、`degraded`、`unavailable`、`not_checked`，两组状态不得混用或互相推导；
- `read-only` 数据及 `degraded`、`unavailable`、`not_checked` 工具能力必须就近展示 `reason`、`evidence`、`remediation`；不得用演示、内存状态或目录身份冒充真实系统能力；
- Desktop 不建立 Task、Session、Chat 页面或领域对象，也不使用这些概念承载配置管理。

### 2.1 Desktop 与 Claude Code 的职责边界

```text
Bandi Desktop
├─ 管理 Agent、组织、Workspace、SOP 等配置资产
├─ 发现缺失配置、外部文件变化与配置文件冲突
├─ 保存 ConfigRevision，支持历史比较与恢复
├─ 治理拟写入长期正式记忆的候选（唯一审核例外）
└─ 提供统一 AI 编程工具入口；Claude Code 支持经验证的 cwd 目录交接

用户自己的 Claude Code + 董事长助理
├─ 明确任务目标并确认方案
├─ 依据配置向部门主管与员工分层委派
├─ 处理执行、阻塞、审批与调整
└─ 完成汇报和验收
```

Desktop 不提供任务创建、任务处理、本次参与人员选择、工作流推进、SOP 运行、任务审批或汇报查看，也不持续同步或重建 Claude Code 的执行视图。用户无需在客户端为每次任务选择部门或员工；董事长助理和部门主管依据组织、岗位、权限与 SOP 配置，在终端完成分层委派。Desktop 不保存有限接入记录，也不创建 Session、WorkflowRun 或 AgentExecution 状态。

全局规则：

- 一级业务导航顺序固定为：概览、Agents、组织、工作区、资产；全部放入 56px 配置管理 Rail，设置和主题沉到底部；
- 最近 Agent 上下文栏最多展示 6 个会话内最近访问 Agent；新 Agent 首次访问时加入列表，切换已有 Agent 只更新选中态、不改变列表排序；无最近 Agent 或用户显式隐藏时不渲染，展开态显示名称与岗位，紧凑态只显示标识；不展示在线、运行、Session、任务或未读状态；
- Agent 上下文栏默认“跟随窗口”：`>=1280px` 展开为 220px，`<1280px` 紧凑为 64px；用户可在“个性化”选择“固定展开”“紧凑显示”或“隐藏”，固定展开在 `960–1279px` 使用 188px、仅在 `<960px` 紧凑显示且不改写偏好，显式隐藏可从个性化设置恢复；
- 展开态栏头直接提供“收起”和“更多”：收起一步切换紧凑栏，更多菜单只承载清空记录与“隐藏此栏”；紧凑态栏头只提供“展开”，不显示更多菜单；
- Agent 使用轻量导航行，当前项通过左侧选中条和浅色背景识别；头像只显示首字符，完整名称只在正文出现；完整 Agents 列表继续由一级 Rail 的 Agents 入口承担，不在上下文栏重复入口；
- 展开态的非当前 Agent 在悬停或键盘聚焦时，于行内右侧垂直居中显示中性的 `×` 直接移除按钮，不越过行边界、不遮挡名称，Tooltip 明确为“从最近记录移除”；当前 Agent 不可移除。单项只有移除操作时不增加二次菜单或右键入口；最近记录只保留在页面内存，当前详情 Agent 作为页面上下文在清空其他记录后仍显示；
- Header 只保留工作区、本地目录和统一的 AI 编程工具入口；当前方案无工具时引导添加，一个工具时直接进入，多个工具时打开选择菜单；
- 多工具菜单按“可继续使用 / 仅配置”分组并使用工具图标；当前仅 Claude Code 支持经过验证的终端交接，其他工具只打开配置入口；
- 设置提供独立“AI 编程工具”分类管理配置方案与工具登记，独立“网络与代理”分类记录全局代理选择，并提供“终端”分类管理默认终端偏好；“已加入”不表示已安装、已探测或可启动；
- Workflow / SOP 从“资产”或 Agent 的“SOP”页签进入；
- 交接入口不展示无真实绑定的 `⌘` 符号；Claude Code 入口展示工作区、cwd 与入口命令，任务交互从进入用户自己的 CLI 后开始；
- 页面标题、导航归属、浏览器标题和原生窗口标题由同一 route metadata 派生；
- 当前 Workspace 只决定配置作用域和打开目录，不等于公司；
- Header 或对象摘要中的能力标记只使用 `real`、`memory-only`、`demo-fixture`、`read-only` 四类；没有证据时不显示成功态；
- “待处理”只统计配置缺失、外部变化、配置文件冲突和待审核正式记忆候选；每项直达具体对象，不形成问题中心；
- `Cmd/Ctrl+S` 只保存当前活动编辑器，沿用字段校验和长期权限确认；无活动编辑器时不拦截。`Cmd+,` 进入设置；Escape 不作为全局取消；
- 不展示会话列表、聊天、工具调用、Todo、日志或 Agent View。

操作规则：

- 首个真实端到端切片固定为 Claude Code `instructions.md`：真实读取 → 编辑 → 基线检查 → 原子写入 → 重读验证 → ConfigRevision；其他配置文件在 Adapter 完成前保持 `read-only`、`memory-only` 或 `demo-fixture`，不得套用真实保存反馈；
- 普通结构化页签使用 `[取消] [保存]`；
- 直接编辑正文或明确文件映射的场景可使用 `[取消] [保存到配置文件]`；
- 保存前始终展示目标文件绝对路径或 `~` 路径；
- 真实 Desktop 保存成功后显示成功文件，不只显示泛化 Toast；当前 Web Mock 只显示“已保存到当前页面内存 · 已记录 memory-only ConfigRevision”，不得使用真实落盘措辞：

```text
当前 Web Mock
✓ 已保存到当前页面内存 · 已记录 r10 · memory-only
目标投影：~/.bandi/agents/agt_zhouce/instructions.md

未来真实 Desktop（写后验证成功后）
✓ 已保存到配置文件 · 已记录 r10
~/.bandi/agents/agt_zhouce/instructions.md
```

- Agent 的停用和归档保留 AgentPackage、正式记忆与历史，并从新委派候选中排除；永久删除放在独立危险区，执行前展示 WorkspaceBinding、共享引用、审核责任和记忆影响，不与“从部门移除”合并；
- 跨部门服务授权逐项配置目标部门、允许能力、Workspace 范围、有效状态和禁止事项；主管默认只能委派本部门 Agent，跨部门选择必须命中有效服务授权；
- 权限收紧直接保存，权限扩大进入 C-04 并要求有权主体确认；
- 用户取消时丢弃当前未保存表单变更，不触碰磁盘；
- 普通 Agent 配置无需“保存草稿 → 审批 → 发布”流程；成功保存直接生成 ConfigRevision；
- `[查看历史]` 在当前文件上下文打开 V-01，不新增一级历史页面；
- “上下文”页签编辑 `config/context.yaml`，包含规划上下文窗口（1,000–2,000,000 Token 的整数）、启用、触发比例、目标比例、保护最近/开头轮次、输出格式和五类非敏感参数绑定；页面按窗口 × 比例展示预计触发/目标 Token，策略关闭时不显示为会触发；OutputProfile destination 固定为 response，不提供文件或网络投递；固定提示 Bandi 不读取当前 Session、token 使用、压缩次数或摘要正文，也不执行压缩；
- WorkspaceBinding 编辑器默认收起“上下文与输出格式覆盖”，每个策略字段可独立覆盖，输出格式和参数可显式选择或继承 Agent 根级；编排 override 只能降低深度、缩小范围、增加要求或禁止，Hook/Command 只维护局部显式引用；查看态只显示继承/覆盖摘要；
- Memory 页签修改正式记忆时不得直接保存，只能提交正式 MemoryCandidate 并进入 M-01；
- 保存过程中满足条件时先进入相应条件 Dialog，确认后仍回到同一保存动作。

六类保存结果不新增页面，统一在当前编辑器、条件 Dialog 或就近状态区反馈：

| 结果 | 页面行为 |
| --- | --- |
| 保存成功 | 返回同一配置查看态，显示证据等级、目标路径、revision 与写后验证证据；`memory-only` 明确刷新即丢失 |
| 校验失败 | 保留编辑态与输入，字段就近报错并聚焦首个错误；不写入、不生成 revision |

- “AI 编程工具”管理共享的当前配置方案、环境内工具登记和逐工具类型化 Adapter 设置；“网络与代理”独立记录代理选择；“终端”记录页面内存中的明确终端偏好，默认是 Terminal.app，不展示或猜测“系统默认终端”。Web 不探测或修改外部应用；Desktop 交接请求只接受冻结的五字段，后端重取 canonical cwd 并仅通过固定 `/usr/bin/open` 请求白名单终端打开目录，不接受 executable、argv、Shell、env、stdin 或脚本，不读取输出，也不表示工具已成功加载；统一入口从全局、工作区或 Agent 进入，当前仅 Claude Code 冻结终端交接 Adapter，其他工具只显示配置入口和能力证据；
- Workspace 的 Company、主责部门、默认负责人和协作部门在创建向导与具体 Workspace 详情中显式管理，不提供设置级默认；
- “配置与备份”同屏管理配置方案、唯一的全局 Agent 根目录、外部变化保护和备份恢复；单方案历史使用 `ConfigRevision`，跨资产快照使用 `BackupSnapshot`，“全部配置”只包含 Bandi 方案元数据而非宿主工具真实配置；Agent 根目录下每个 Agent 使用稳定 ID 的独立目录，不随部门或工作区变化；当前 Web Mock 不创建、移动或扫描真实目录；
- “外部变化保护”只配置发现外部变化的偏好；多个终端或编辑器的并发写入统一表现为相对编辑基线的外部变化并通过 Diff 处理，Bandi 不识别终端或会话状态，当前 Web Mock 也不执行扫描；
- 当前 Web Mock 中可编辑业务设置只保存到 React 页面内存，刷新恢复初始数据；仅严格白名单、版本化的 `UiPreferences` 使用单一 `localStorage` key；本机 Logo 与背景图使用固定桌面资源槽位；
- 个性化保持单页，通过原生页内锚点定位品牌、主题、显示、布局和背景，不增加二级菜单；合法草稿临时应用到当前真实工作台，保存后保留，取消、放弃离开或未保存卸载后恢复已保存外观；
- 图片填充与遮罩仅在存在背景图时显示；“恢复默认”先重置草稿并标记图片待清理，仍需统一保存才能应用，保存前可通过取消或离开保护撤销；
- 窄屏个性化保存条改为单列操作并为页面末尾预留空间，不得遮挡字段焦点或造成页面横向滚动；
- Agent 上下文栏的有效矩阵为：用户显式选择“隐藏”时所有宽度均不渲染，没有会话内最近 Agent 时也自动隐藏；跟随窗口仅在 `>=1280px` 展开为 220px，固定展开在 `960–1279px` 使用 188px、在 `<960px` 紧凑为 64px，紧凑显示在所有宽度使用 64px；隐藏或窄屏降级不改写其他状态，56px 配置管理 Rail 始终保留，用户可在此进入“设置 → 个性化”恢复；
- 共享资产影响、长期权限扩大、恢复、永久删除和正式 Memory 审核是具体操作满足条件时出现的规则，不是设置项，也不提供开关。

## 27. 已确认决策

1. 一级导航固定为概览、Agents、组织、Workspaces、资产，设置沉底；
2. 删除一级“运行”和一级“工作流”，不新增“候选”或“发布中心”；
3. Workflow / SOP 归入资产，并作为 Agent 配置模块提供；
4. Agent 详情是完整配置核心页，至少包含概览、AgentPackage、身份与职责、Instructions、Skills、Memory、Rules、MCP、权限、Workspaces 和 SOP；AgentPackage 以完整目录树 + Viewer 呈现；
5. 普通配置不引入草稿发布链路；当前 Web Mock 统一使用 `[取消] [保存]`，真实 Desktop 接入文件写入后可对明确文件映射使用 `[取消] [保存到配置文件]`；
6. 编辑时显示保存目标；当前 Web Mock 成功后显示页面内存 ConfigRevision，真实 Desktop 仅在写后验证成功后显示实际写入文件；
7. Agent、Workspace、SOP 和文件可按实际能力提供编辑器、Finder、终端、复制路径和 Claude Code 衔接操作；当前 Web Mock 只展示明确标注的演示反馈，不访问系统、剪贴板或进程；
8. 来源与有效配置只用于按需诊断，不成为默认主流程或独立一级页面；
9. 共享配置影响、外部并发修改 Diff、配置文件冲突和长期权限扩大使用条件 Dialog；
10. 正式记忆审核 Dialog 保留，且只处理拟写入正式长期记忆的候选；
11. 配置概览关注最近保存版本、配置缺失、外部变化、配置文件冲突、待审核正式记忆候选和快捷入口；
12. Desktop 所有页面只做多 Agent 组织与配置管理，不创建、接收或处理任务；
13. 任务目标、方案确认、部门/员工分配、执行、阻塞、审批、汇报和验收，全部在用户自己的 Claude Code 与董事长助理中完成；
14. 用户无需在客户端为每次任务选择部门或员工，董事长助理和部门主管依据配置在终端分层委派；
15. SOP 页只编辑步骤、责任部门/岗位、输入输出、依赖和确认/升级条件等定义，不运行、推进或产生 Desktop 待办；
16. 配置概览和其他管理页面不承担运行监控；
17. Claude Code 保留聊天、工具调用、Todo、日志、Agent View 和其他任务交互及执行中间状态；
18. Desktop 不镜像、推断或伪造 Claude Code 的执行状态；
19. “打开 Claude Code”只负责经验证的 cwd 目录交接，不生成或执行宿主命令，也不代表任务、Plugin、Session 或 SOP 已启动；
20. Desktop 不保存接入、启动、Session 或执行记录；
21. Workspace 是目录与配置作用域，不等于公司，也不是运行实例；
22. 共享配置修改必须展示影响范围，长期权限扩大必须二次确认；
23. 编辑期间外部修改不得被静默覆盖，配置文件冲突必须解决后保存；
24. Memory Review 是正式记忆治理例外，只处理拟写入长期正式记忆的候选；
25. 正式记忆写回成功与 Claude Code Runtime 是否加载是不同事实；
26. 组织页使用组织树管理 Company、部门上下级、主管、岗位、成员和委派边界；首版通过选择上级部门调整层级；
27. 组织关系必须无环，删除有成员或下级的部门前先迁移；移动组织只改变关系，不改写 AgentPackage 配置；
28. 设置以“配置与备份”为稳定分类，同屏管理唯一 Agent 根目录、外部变化保护、手动/自动快照、历史和按范围恢复；创建与恢复使用 Dialog，恢复前先保存当前状态；
29. Bandi 创建的 Git 备份仓库固定为 Private，不提供公开选项；凭据与执行过程永不备份，正式记忆远程备份需单独确认；
30. 每个已关联组织的 Workspace 只能有一个主责部门和默认项目负责人，可有多个协作部门；主责主管承担总体结果、公共记忆归口和跨部门汇总，各协作主管只负责本部门交付与部门项目记忆；
31. 更换 Workspace 主责部门必须显式确认，保留公共记忆、部门记忆和历史，不自动修改 AgentPackage 或 WorkspaceBinding；
32. Workspace 可以暂不关联组织，但首版最多归属一个 Company；主责、项目负责人和协作部门必须来自该 Company，不跨公司合并组织、普通默认、共享引用或安全边界；
33. 更换或解除 Workspace 所属 Company 必须展示失效影响并重新选择项目责任关系；目录、公共记忆和历史不删除，旧公司部门记忆保留为只读历史；
34. Agent 最多一个主属部门，可有多个带能力、Workspace 与禁止事项边界的服务授权；服务关系不改变直属主管或授予目标部门管理权；
35. Agent 停用或归档保留 AgentPackage、正式记忆和历史且不可接受新委派；永久删除必须独立高风险确认；
36. 共享资产首版默认 Company 内共享，跨 Company 必须单独注册和授权；局部定制进入 Agent 自有配置，删除前处理全部有效引用；
37. 组织身份不自动授予权限；Agent 可收紧但不能自行扩大，权限扩大必须向上报告并由有权主体确认；
38. AgentPackage 使用稳定 `agent-id` 目录且不随部门移动；根级配置与 `workspaces/<workspace-id>/` 专属配置分层，表单和外部文件编辑映射同一真实资产；
39. 首次安装以“导入已有 Agent”为主操作、“创建个人 Agent”为次操作；Workspace、Company、Department、Role、Plugin 和 `/bandi:bandi` 均为按需增强；
40. Skill 本体安装、更新、回滚和卸载与 Agent/WorkspaceBinding 显式引用分离，生命周期动作不隐式修改引用；
41. 当前 Web Mock 的 onboarding、扫描、Skill 操作与快照只保存在页面内存，不伪装真实系统能力；
42. 个人 Agent 的 Company、Department、Role 可全部为空；只有三者完整且同作用域时才是组织 Agent，部分填写属于非法状态；
43. Claude Agent 首期仅支持用户明确选择的单文件两阶段导入，不自动扫描或批量导入，也不自动转换 `CLAUDE.md`、Rules、Skills、MCP 或正式 Memory。
