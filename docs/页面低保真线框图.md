# 班底页面低保真线框图

> 文档版本：v1.5-draft
> 更新日期：2026-08-29
> 状态：配置管理平面线框收敛稿
> 关联文档：[《产品与页面架构》](./产品与页面架构.md)

## 1. 本轮收敛目标

v1.4-draft 将 Bandi Desktop 收敛为 Claude Code 多 Agent 配置管理平面：

- 一级导航固定为：首页、Agents、组织、Workspaces、资产、设置；
- Workflow / SOP 作为资产与 Agent 配置模块存在，不设一级“工作流”；
- 删除一级“运行”，不新增“候选”或“发布中心”；
- Agent 详情升级为完整配置核心页，配置查看、编辑、保存和文件落点在同一上下文完成；
- 首页关注最近保存版本、配置缺失、外部变化、配置文件冲突、待审核正式记忆候选和快捷入口，不承担运行监控；
- Desktop 所有页面只管理多 Agent 的组织关系与配置资产，不创建、接收或处理任务；
- 任务目标、方案确认、部门/员工分配、执行、阻塞、审批、汇报和验收，全部在用户自己的 Claude Code 中由董事长助理协同完成；
- 用户无需在 Desktop 为每次任务选择部门或员工，董事长助理和部门主管依据已保存配置在终端分层委派；
- Claude Code 保留全部任务交互与执行中间状态，Desktop 不镜像聊天、工具调用、Todo、日志或 Agent View；
- 来源与有效配置只在排错、追溯和冲突处理时按需展开，不占据默认主流程；
- SOP 页面只编辑定义，不运行 SOP；正式记忆审核是唯一审核例外；长期权限扩大、恢复、删除和共享影响都称为当前操作的风险确认。

本轮不锁定最终颜色、字体、图标、圆角和字段级交互。

## 2. 线框约定与产品边界

- `[按钮]`：操作；
- `(状态)`：只读状态；
- `▼`：切换或展开；
- `⋯`：更多操作；
- `!`：异常、限制或需确认；
- `● / ○`：选择；
- 路径、命令、版本和哈希在正式 UI 中使用等宽字体；
- “保存”表示将变更写入明确展示的配置文件，不引入独立草稿/发布中心；
- “正式记忆候选”仅指拟写入长期正式 MemorySpace 的候选，不包括 Todo、聊天摘要、工具结果、过程日志或临时上下文。

### 2.1 Desktop 与 Claude Code 的职责边界

```text
Bandi Desktop
├─ 管理 Agent、组织、Workspace、SOP 等配置资产
├─ 发现缺失配置、外部文件变化与配置文件冲突
├─ 保存 ConfigRevision，支持历史比较与恢复
├─ 治理拟写入长期正式记忆的候选（唯一审核例外）
└─ 提供“在 Claude Code 中继续”的 cwd / 命令衔接

用户自己的 Claude Code + 董事长助理
├─ 明确任务目标并确认方案
├─ 依据配置向部门主管与员工分层委派
├─ 处理执行、阻塞、审批与调整
└─ 完成汇报和验收
```

Desktop 不提供任务创建、任务处理、本次参与人员选择、工作流推进、SOP 运行、任务审批或汇报查看，也不持续同步或重建 Claude Code 的执行视图。用户无需在客户端为每次任务选择部门或员工；董事长助理和部门主管依据组织、岗位、权限与 SOP 配置，在终端完成分层委派。Desktop 不保存有限接入记录，也不创建 Session、WorkflowRun 或 AgentExecution 状态。

全局规则：

- 一级导航顺序固定为：首页、Agents、组织、Workspaces、资产、设置；
- Workflow / SOP 从“资产”或 Agent 的“SOP”页签进入；

- 当前 Workspace 只决定配置作用域和打开目录，不等于公司；
- “待处理”只统计配置缺失、外部变化、配置文件冲突和待审核正式记忆候选；每项直达具体对象，不形成问题中心；
- 不展示会话列表、聊天、工具调用、Todo、日志或 Agent View。

- 没有问题时展示“配置已就绪”和主要快捷入口，不补充运行指标填充页面；
- 可显示最近打开的 Workspace，但不显示 Session 活跃数、Token、耗时或执行进度。

组织页使用“组织树 + 节点详情”呈现长期关系和配置健康度，不复制传统后台的排序号、创建时间等低价值字段，也不显示 Agent 在线、执行中或会话状态。公司和部门节点都可添加下级；首版通过表单选择上级部门完成移动，不优先提供拖拽。

组织编辑规则：

- Department 使用父节点形成树，界面建议不超过三层；超过时提示复杂度，但底层不硬编码层数；
- 创建或移动必须阻止循环；主管应属于当前部门或具有明确管理授权；
- 删除有下级或成员的部门时，先选择迁移到上级、其他部门或暂时未归属；不得删除 AgentPackage；
- 移动部门或 Agent 只改变组织与委派关系，不修改 Agent 的 Skills、Rules、MCP、权限和 WorkspaceBinding；若原委派不再成立，只报告配置缺口。

- 用户取消时丢弃当前未保存表单变更，不触碰磁盘；
- 普通 Agent 配置无需“保存草稿 → 审批 → 发布”流程；成功保存直接生成 ConfigRevision；
- `[查看历史]` 在当前文件上下文打开 V-01，不新增一级历史页面；
- Memory 页签修改正式记忆时不得直接保存，只能提交正式 MemoryCandidate 并进入 M-01；
- 保存过程中满足条件时先进入相应条件 Dialog，确认后仍回到同一保存动作。

## 28. 已确认决策

1. 一级导航固定为首页、Agents、组织、Workspaces、资产、设置；
2. 删除一级“运行”和一级“工作流”，不新增“候选”或“发布中心”；
3. Workflow / SOP 归入资产，并作为 Agent 配置模块提供；
4. Agent 详情是完整配置核心页，至少包含概览、身份与职责、Instructions、Skills、Memory、Rules、MCP、权限、Workspaces、SOP、文件；
5. 普通配置直接使用 `[取消] [保存]` 或 `[取消] [保存到配置文件]`，不引入草稿发布链路；
6. 编辑时显示保存目标，成功后显示实际写入文件；
7. Agent、Workspace、SOP 和文件提供在编辑器打开、Finder 中显示、终端打开目录、复制路径和打开 Claude Code 等适用操作；
8. 来源与有效配置只用于按需诊断，不成为默认主流程或独立一级页面；
9. 共享配置影响、外部并发修改 Diff、配置文件冲突和长期权限扩大使用条件 Dialog；
10. 正式记忆审核 Dialog 保留，且只处理拟写入正式长期记忆的候选；
11. 首页关注最近保存版本、配置缺失、外部变化、配置文件冲突、待审核正式记忆候选和快捷入口；
12. Desktop 所有页面只做多 Agent 组织与配置管理，不创建、接收或处理任务；
13. 任务目标、方案确认、部门/员工分配、执行、阻塞、审批、汇报和验收，全部在用户自己的 Claude Code 与董事长助理中完成；
14. 用户无需在客户端为每次任务选择部门或员工，董事长助理和部门主管依据配置在终端分层委派；
15. SOP 页只编辑步骤、责任部门/岗位、输入输出、依赖和确认/升级条件等定义，不运行、推进或产生 Desktop 待办；
16. 首页和其他管理页面不承担运行监控；
17. Claude Code 保留聊天、工具调用、Todo、日志、Agent View 和其他任务交互及执行中间状态；
18. Desktop 不镜像、推断或伪造 Claude Code 的执行状态；
19. “打开 Claude Code”只负责 cwd / 命令衔接，不代表任务、Session 或 SOP 已启动；
20. Desktop 不保存接入、启动、Session 或执行记录；
21. Workspace 是目录与配置作用域，不等于公司，也不是运行实例；
22. 共享配置修改必须展示影响范围，长期权限扩大必须二次确认；
23. 编辑期间外部修改不得被静默覆盖，配置文件冲突必须解决后保存；
24. Memory Review 是正式记忆治理例外，只处理拟写入长期正式记忆的候选；
25. 正式记忆写回成功与 Claude Code Runtime 是否加载是不同事实；
26. 组织页使用组织树管理 Company、部门上下级、主管、岗位、成员和委派边界；首版通过选择上级部门调整层级；
27. 组织关系必须无环，删除有成员或下级的部门前先迁移；移动组织只改变关系，不改写 AgentPackage 配置；
28. 设置中提供独立“备份与恢复”入口；本地备份支持手动/自动快照、历史和按范围恢复，恢复前先保存当前状态；
29. Bandi 创建的 Git 备份仓库固定为 Private，不提供公开选项；凭据与执行过程永不备份，正式记忆远程备份需单独确认；
30. 每个已关联组织的 Workspace 只能有一个主责部门和默认项目负责人，可有多个协作部门；主责主管承担总体结果、公共记忆归口和跨部门汇总，各协作主管只负责本部门交付与部门项目记忆；
31. 更换 Workspace 主责部门必须显式确认，保留公共记忆、部门记忆和历史，不自动修改 AgentPackage 或 WorkspaceBinding；
32. Workspace 可以暂不关联组织，但首版最多归属一个 Company；主责、项目负责人和协作部门必须来自该 Company，不跨公司合并组织、普通默认、共享引用或安全边界；
33. 更换或解除 Workspace 所属 Company 必须展示失效影响并重新选择项目责任关系；目录、公共记忆和历史不删除，旧公司部门记忆保留为只读历史；
34. Agent 最多一个主属部门，可有多个带能力、Workspace 与禁止事项边界的服务授权；服务关系不改变直属主管或授予目标部门管理权；
35. Agent 停用或归档保留 AgentPackage、正式记忆和历史且不可接受新委派；永久删除必须独立高风险确认；
36. 共享资产首版默认 Company 内共享，跨 Company 必须单独注册和授权；局部定制进入 Agent 自有配置，删除前处理全部有效引用；
37. 组织身份不自动授予权限；Agent 可收紧但不能自行扩大，权限扩大必须向上报告并由有权主体确认；
38. AgentPackage 使用稳定 `agent-id` 目录且不随部门移动；根级配置与 `workspaces/<workspace-id>/` 专属配置分层，表单和外部文件编辑映射同一真实资产。
