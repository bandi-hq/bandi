> 文档版本：v1.3-draft
> 更新日期：2026-08-29
> 状态：分层记忆与项目记忆治理线框确认稿
> 关联文档：[《产品与页面架构》](./产品与页面架构.md)

## 1. 本轮确认目标

本轮线框确认：

- Bandi 是否呈现为现实创业公司的本地数字孪生；
- 公司、部门、岗位、Agent、Workspace、Workflow、策略和证据的关系是否清晰；
- Bandi Desktop 是否保持管理平面，而非另一套 Claude Code；
- Plugin、Local Service、系统 CLI 和 Claude Code 的集成状态是否可理解；
- `[进入 Bandi ▾]` 是否能准确拆分“快速接入当前会话”和“完整启动新会话”；
- `/bandi:bandi`、可选 `/bandi` 和自然语言语义触发是否被准确表达；
- Attachment、Launch、WorkflowRun 和 AgentExecution 是否按证据展示；
- 董事长助理、部门主管和获授权专业 Agent 的分层编排是否清晰；
- 五类 MemorySpace 的所有者、归口人、审核人和隔离边界是否清晰；
- MemoryCandidate 的 Diff、审核、写回与 MemoryProjection 来源是否可解释。

本轮不锁定最终颜色、字体、图标、圆角和字段级交互。

## 2. 线框约定

- `[按钮]`：操作；
- `(状态)`：只读状态；
- `▼`：切换或展开；
- `⋯`：更多操作；
- `!`：异常或限制；
- `● / ○`：选择；
- `L0 / L1 / L2`：配置事实、有限事件证据、可靠 Runtime 证据；
- 路径、命令、版本和哈希在正式 UI 中使用等宽字体；
- 示例公司表示现实公司的数字孪生，不是虚拟公司模板。

## 27. 已确认决策

1. 第一屏继续 Workspace 优先，但 Workspace 不等于公司；
2. 公司详情升级为现实公司数字孪生核心关系页；
3. Desktop 是管理平面，不内嵌 Claude Code；
4. 董事长助理是用户主要 CLI 入口，主管和员工由 Workflow 分层委派；
5. 编排能力由授权决定，不由身份标签硬编码；
6. 全局主操作改为 `[进入 Bandi ▾]`；
7. `attach_current` 与 `launch_new` 严格分离；
8. `/bandi:bandi` 是标准 Plugin 入口；
9. `/bandi` 只有额外安装薄别名后才可用；
10. 自然语言只是语义触发候选；
11. Bandi 自有 Plugin 与第三方 Plugin SourceAsset 分离；
12. Plugin、MCP、Hooks、Local Service 和 Session 状态分开；
13. 首版支持 L0/L1，L2 Runtime Connector 后续实现；
14. Attachment、Launch、WorkflowRun 和 AgentExecution 不统一伪装成运行实例；
15. 首版项目记忆以 Workspace 为边界，不新增并列 Project 对象；
16. 每个长期 Agent 都有跨项目长期记忆和每个 Workspace 独立项目记忆；
17. 董事长助理项目管理记忆与 Workspace 公共记忆分开；
18. Workspace 公共记忆归 Workspace 所有、由助理归口；部门项目记忆归 Department × Workspace、由主管归口；
19. 记忆编辑先提交 MemoryCandidate，提议者不能自审；
20. MemoryProjection 展示来源、版本、哈希、纳入原因与权限结果，不静默覆盖冲突；
21. 不新增一级记忆导航，治理入口嵌入 Workspace、公司、部门、Agent 和外部资产页面。
