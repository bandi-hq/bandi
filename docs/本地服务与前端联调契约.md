> 文档版本：v1.4-frozen
> 更新日期：2026-09-02
> 状态：首版已实现切片冻结契约
> 关联文档：[《产品与页面架构》](./产品与页面架构.md) · [《技术架构》](./技术架构.md) · [《首版能力矩阵》](./首版能力矩阵.md)

## 1. 范围

本文冻结 Bandi Desktop 前端与 Rust Local Service 当前已实现切片的跨进程语义：授权根内只读发现、共享资产引用图、编辑器加载、Agent 全配置族保存、外部基线变化、诊断、配置版本、Workspace/Organization、四类正式 Memory、本地 Backup/Restore 和 AI 编程工具工作区交接。核心线形 DTO 在本文直接列出；Organization、Memory、Backup 与共享资产图的可执行 JSON Schema 和跨语言 fixture 位于 `packages/contracts/`。名称、字段、必填性和枚举值不得由 Rust 或 TypeScript 单方面改变。

Local Service 内部的 `ResolveTarget`、`ValidateEdit`、`RestrictedConfigWriter` 等名称不是 wire API。传输可使用 Tauri Command 或受限 localhost API，但不得因此改变本文 DTO 的业务语义。

本契约不包含：

- Task、WorkflowRun、Assignment、任务 Handoff 或执行期 Approval；`RequestClientHandoff` 仅表示 Desktop 向外部 AI 编程工具请求工作区交接，不是任务交接；
- 一次性工具权限持久化；
- Session 创建、attach、停止、恢复或跟踪；
- 聊天、Todo、工具调用、日志、Usage 或 Agent View 镜像；
- Desktop SOP 执行器；
- 未在本文登记的客户端 Adapter、通用启动参数、Provider、Model、账户或 Quota；
- Plugin / MCP 直接写 SQLite、AgentPackage 或正式 Memory；
- 任意 Shell API；
- 首轮远程 Git、多设备同步或自动冲突合并协议。

## 2. 通用序列化规则

```ts
type Id = string
type Timestamp = string // RFC 3339 UTC，例如 2026-08-31T10:42:00Z
type ContentHash = `sha256:${string}`
type RelativeAssetPath = string
type AbsoluteSystemPath = string
type RootKind = 'workspace' | 'claude_user' | 'managed' | 'bandi' | 'authorized_external'
type OfficialScope = 'user' | 'project' | 'local' | 'managed' | 'bandi'
type CapabilityStatus = 'supported' | 'degraded' | 'unavailable' | 'not_checked'

type CapabilityFactDto = {
  status: CapabilityStatus
  reason: string
  evidence: string[]
  remediation: string[]
}
```

- JSON 字段使用 `camelCase`，枚举值使用稳定 ASCII `snake_case`。
- Rust DTO 必须显式使用与 wire 形状等价的 Serde 标注：结构体字段采用 `#[serde(rename_all = "camelCase", deny_unknown_fields)]`；以 `kind` 判别的联合采用 `#[serde(tag = "kind", rename_all = "snake_case")]`，各分支 payload 与本文扁平 JSON 一致。不能依赖 Rust 默认枚举编码或默认忽略未知字段。
- 本文冻结的请求、结果、事件和其嵌套业务 DTO 均拒绝未知字段；TypeScript runtime codec / JSON Schema 与 Rust `deny_unknown_fields` 必须使用同一 fixture 验证。这样既保证 `RequestClientHandoff` 恰好五字段，也防止 `SaveConfigRequest` 被额外路径或未冻结 kind 扩展。
- 持久化对象 ID 由 Local Service 生成且对调用方不透明；除第 10 节明确不允许 `requestId` 的工作区交接外，带 `requestId` 的调用由调用方生成，仅用于幂等和关联。
- 时间统一传 RFC 3339 UTC，不传“刚刚”“昨天”等展示文本。
- 内容哈希必须携带算法前缀。
- 写操作以稳定 `assetId` 定位。AgentPackage 内路径使用不含 `..` 的规范相对路径；绝对路径由 Local Service 返回和校验，`~` 只用于 UI 展示。
- 字段缺失表示“未提供”；`null` 仅用于 Schema 明确允许的清除语义；空字符串是实际值，不与前两者混用。
- 前端不得根据中文文案判断业务分支，只判断 `kind`、`code` 等稳定字段。
- secret 必须在 Local Service 内脱敏；前端 DTO 不传 secret 原文，不能用 CSS 隐藏代替脱敏。
- 所有可用性或接入能力必须使用 `CapabilityFactDto`；`reason` 解释结论，`evidence` 只列可验证事实，`remediation` 只列用户可执行的补救动作。`not_checked` 不得被前端展示为可用，`degraded` 必须说明仍可完成的降级路径，`unavailable` 不得生成或执行猜测性命令。

## 3. 资产定位、发现与编辑器加载


`RegisterWorkspaceRequest` 只来自 Desktop 系统目录选择器完成后的明确登记；Local Service 必须拒绝相对路径、符号链接授权根、非目录和重复 canonical path，并将规范路径保存到 Workspace Registry。纯 Web 不调用该接口，页面内演示路径不成为后端可信事实。

Desktop 外部 AgentPackage 引用通过 `register_external_agent` 登记，wire 只保存严格校验的 Agent metadata 与 canonical root。登记只检查用户明确选择的根目录本身：拒绝相对路径、缺失目录、文件和符号链接根；不得枚举目录、读取 `agent.yaml`、发现 Skills/Rules/MCP/Memory、复制、缓存、软链接或修改外部内容。`list_agents` 统一返回受管 Agent 与外部引用，读取外部记录时只读 SQLite metadata，不再次访问外部目录；外部来源永久只读。显示名称可使用中文并可修改，技术 `agent-id` 由前端以原生 UUID 生成，在同一次创建意图及失败重试中保持稳定，创建后不可修改，Rust 仍执行最终 ASCII ID 校验。

Claude Agent 真实导入与上述 reference-only 严格分离。`preview_claude_agent` 只接受用户明确选择的绝对 `.md` 普通文件，拒绝 symlink、非 UTF-8、超过 256 KiB 及不直接位于 `.claude/agents` 的来源；返回 `ClaudeAgentPreviewDto { sourcePath, sourceBaselineHash, name, description?, instructions, recognizedFields, ignoredFields }`，不写文件或数据库。`import_claude_agent` 必须携带预览 hash 和独立确认，后端重读并在变化时返回 `CLAUDE_AGENT_SOURCE_CHANGED`；后端还必须校验受管 `instructions.md` 等于复核后的正文、拒绝额外头像，并覆盖客户端 provenance 为 `claude-agent-import / managed-copy`，然后复用 `commit_managed_agent_creation`。原文件永不修改，未识别 frontmatter 不自动映射到 Rules、Skills、MCP、权限或正式 Memory。

设置页“本地访问边界”是前端只读派生视图：直接从已 hydration 的 `state.workspaces` 和 `state.agents[].packageSource` 去重生成受管 AgentPackage、已登记 Workspace、Claude Agent 导入来源与外部引用四组路径。它不新增 command、DTO、授权记录或 OS 权限状态，也不改变上述 preview hash、独立确认和提交复核 wire 契约。首版不引入 selection token。

Organization/Workspace 领域 wire 已冻结为 `OrganizationSnapshot { schemaVersion: 1, companies, departments, roles, workspaces, serviceGrants }`，字段使用 camelCase，未知字段拒绝；共享 schema 与双端 fixture 位于 `packages/contracts/schemas/organization-snapshot.schema.json` 和 `packages/contracts/fixtures/organization-snapshot.valid.json`。Desktop 启动调用 `load_organization_snapshot`，即使数据库为空也使用空快照替换 Web demo fixture；数据库损坏或 migration 失败必须展示错误，不得静默退回演示事实。保存命令限于 `save_company / save_department / save_role / save_workspace / save_service_grants`，实体稳定 ID 由 `generate_entity_id` 签发；同一创建对话框内失败重试必须复用首次签发的 ID。前端成功后必须使用后端返回的 canonical DTO 回写当前状态，不能继续使用提交前草稿冒充持久化结果。`save_workspace` 必须从 Registry 重取 canonical path 并拒绝前端 path 不一致；旧 JSON Registry 仅用于兼容导入。公司助理、部门主管和 Workspace 默认负责人新任命时必须存在、属于同一 Company 且状态为 `active`；前端只展示合法候选，Rust 对创建和保存执行同一最终校验。普通历史成员可保留 inactive/archived，但仍须存在且同公司。ServiceGrant 的 wire 项包含显式 `agentId`，按 Agent 在单个 SQLite 事务中整体替换。Workspace 索引移除不删除目录、Agent WorkspaceBinding、MemorySpace、资产或历史；存在 ServiceGrant 引用时当前实现拒绝移除，并返回可展示诊断。

AgentPackage 文件与 Organization SQLite 之间不承诺单一 ACID 事务。受管 Agent 创建和身份编辑必须通过 `commit_managed_agent_creation` / `commit_managed_agent_identity` 高层命令提交，并在首次文件写入前持久化 recovery operation。Agent 组织关系 wire 可省略：`companyId / primaryDepartmentId / roleId` 全空表示个人 Agent，三者完整且同作用域表示组织 Agent，部分填写必须拒绝。状态固定为 `prepared → filesystem_committed → revision_pending / organization_pending → completed`，无组织 Agent 在 revision 完成后直接进入 `completed`；无法安全继续时进入 `blocked`。`continue_agent_recovery` 只继续未完成阶段：当前文件 hash 匹配时跳过重写，hash 不匹配时转为 `blocked` 且绝不覆盖。前端启动只通过 `list_agent_recovery_summaries` hydrate 未完成摘要，不自动执行写入；用户可从首页待处理区域明确继续。恢复状态可跨页面、跨重启保持，completed 重试返回既有事实。Workspace Registry 的登记与 Workspace SQLite 保存仍按各自 canonical 事实恢复，不宣称跨存储原子事务。

发现只读取已经登记和授权的 Workspace、Claude 用户配置根及明确授权外部根，不导入、不安装、不改写文件。用户配置根从 `CLAUDE_CONFIG_DIR` 或 Claude Code 默认规则解析；项目配置只在目标 Workspace 下发现。`managed` 和 Plugin cache 可作为只读证据，但 cache 不成为普通资产或恢复目标。

`SourceContainerDto` 表示物理文件/目录；`SourceAssetSummaryDto` 表示其中逻辑 fragment。当前 wire 已冻结 `identity / instructions / context / rules / skills / mcp / permissions / sop / orchestration / hooks / commands / workspace_binding`，对应受管 current v1 AgentPackage 的 canonical 文件。一个 container 可以有多个 asset。前端保存只能提交稳定 `assetId` 与服务签发的 `baselineRef`，不能提交任意绝对写入路径。

`SharedAssetNodeDto.id` 是被引用共享资产的逻辑稳定 ID，不能与 `SourceAssetSummaryDto.id`（配置文件或 fragment 自身身份）混用。Desktop 只从后端派生的 `<app-data>/shared-assets/` 受限根发现共享本体，校验普通目录、`asset.yaml`、单文件 `contentFile`、symlink 边界以及 Company/Department 显式登记。引用状态依次区分无效目标、类型错误、缺少 referrer Company 事实、Company 越界、正常解析和目标缺失。共享根不存在时目标缺失仍为 `unresolved`，共享根可读取但目标不存在时才是 `dangling`。当前共享资产能力只读，不包含创建、编辑、删除、安装或跨 Company 独立授权事务。共享合同见 `packages/contracts/schemas/asset-reference-graph.schema.json`。

## 4. 基础诊断

```ts
type Diagnostic = {
  code: string
  severity: 'error' | 'warning' | 'info'
  message: string
  field?: string
  path?: RelativeAssetPath
  range?: {
    startLine: number
    startColumn: number
    endLine: number
    endColumn: number
  }
  remediation?: string
}
```

`code` 是行为判断依据，`message` 是可直接展示的本地化文本。前端必须能通用展示未知 `code`，不能因未知诊断而丢失错误信息。字段级错误尽量提供 `field`，原文错误尽量提供 `path` 和 `range`。当前稳定 code family 已覆盖 package legacy/future/unverified、manifest 无效、Role 缺失/作用域不匹配、Orchestration 非法/扩权/有环、Hook/Command/OutputProfile kind 或引用错误、共享资产及引用异常、Plugin 不完整/不兼容和 parameter binding 无效；前端不得从中文 message 反推分支。新增 code 必须保持未知 code 可展示并补对应合同或领域测试。

## 5. 普通配置保存

### 5.1 请求

现有前端 `apps/web/src/agent-config-model.ts` 的 `AgentConfigPayload` 可继续作为页面内判别联合思路，但不能直接作为 wire DTO。跨进程请求必须包含目标资产和编辑基线。

```ts
type InstructionsConfigChange = {
  kind: 'instructions'
  value: string
}

type ContextConfigChange = {
  kind: 'context'
  value: string
}

type RulesConfigChange = {
  kind: 'rules'
  value: string
}

type SkillsConfigChange = {
  kind: 'skills'
  value: string
}

type McpConfigChange = {
  kind: 'mcp'
  value: string
}

type PermissionsConfigChange = {
  kind: 'permissions'
  value: string
}

type SopConfigChange = {
  kind: 'sop'
  value: string
}

type OrchestrationConfigChange = {
  kind: 'orchestration'
  value: string
}

type HooksConfigChange = {
  kind: 'hooks'
  value: string
}

type CommandsConfigChange = {
  kind: 'commands'
  value: string
}

type SaveConfigRequest = {
  requestId: Id
  assetId: Id
  change: InstructionsConfigChange | ContextConfigChange | RulesConfigChange | SkillsConfigChange | McpConfigChange | PermissionsConfigChange | SopConfigChange | OrchestrationConfigChange | HooksConfigChange | CommandsConfigChange
  expectedBaseline: BaselineRefDto
  baseContent: string
  confirmationRef?: Id
}
```

当前保存切片只允许 `change.kind === 'instructions' | 'context' | 'rules' | 'skills' | 'mcp' | 'permissions' | 'sop' | 'orchestration' | 'hooks' | 'commands' | 'workspace_binding'`。Instructions 的 `value` 是 `instructions.md` 完整规范文本；Context 的 `value` 是 `config/context.yaml` 完整规范 YAML，固定包含 `schemaVersion: 1`、完整 `contextPolicy`、根级 `contextWindowTokens`、可为空字符串的 `outputProfileId` 和 `outputParameterBindings`。`contextWindowTokens` 必须是 1,000–2,000,000 的整数；读取缺少该字段的既有 v1 文件时使用 200,000，后续规范保存补写该字段。ContextPolicy 比例与轮次范围必须与页面校验一致；参数绑定仅允许 string、number、boolean、string-list、enum 的非敏感值，标识不得重复。Rules、Skills、MCP 与 SOP 的 `value` 分别是 `config/rules.yaml`、`config/skills.yaml`、`config/mcp.yaml`、`config/sop.yaml` 完整规范 YAML，固定包含 `schemaVersion: 1` 与最多 500 个不重复、格式合法的稳定资产 ID。Permissions 的 `value` 是 `config/permissions.yaml` 完整规范 YAML，固定包含 `schemaVersion: 1` 与 `permissions.files / commands / network / delegation` 四个非空字符串字段，拒绝未知字段、NUL 和超过 256 字节的单项。引用保存不表示 OutputProfile、Rule、Skill、MCP 或 SOP 已安装、已连接、被宿主加载、当前 Session 已应用或被 Bandi 执行；Skill 的安装、更新、回滚和卸载以及 MCP 的凭据与连接验证仍是独立生命周期。SOP 引用保存只维护供 Claude Code 助理解析的显式关系，不创建任务、选择人员、产生待办、启动或推进流程。Permissions 保存只修改长期边界，不表示当前 Session、进程或宿主工具权限已改变。Orchestration 的 `value` 是 `config/orchestration.yaml` 完整规范 YAML，保存是否允许委派、0–32 的最大深度、Agent/Role/Department 稳定 ID 范围、WorkspaceBinding/SOP/跨部门 ServiceGrant 必需条件、升级目标与条件及禁止事项；每类范围最多 500 个不重复稳定 ID，条件与禁止事项每类最多 100 项、每项最多 512 字符。该策略只表达长期静态边界，有效委派仍是权限、组织关系、ServiceGrant 与策略的交集；保存不创建任务、不选择人员、不审批、不推进流程且不管理 Session。Hooks 与 Commands 的 `value` 分别是 `config/hooks.yaml`、`config/commands.yaml` 完整规范 YAML，固定包含 `schemaVersion: 1` 和最多 500 个不重复的对应稳定资产引用；每个引用最多 100 个不重复参数绑定，参数只允许 `string / number / boolean / string-list / enum` 非敏感值。string 与 enum 最多 4096 字符且禁止 NUL，string-list 最多 100 项且每项遵循相同文本限制，number 必须为有限值。前端还必须按对应 HookDefinition 或 CommandDefinition 校验参数是否存在、类型、必填项、数字范围和 enum options。保存仅维护定义引用和参数，不接受脚本文本、Shell、cwd、环境变量、executable、argv、stdin 或执行期输入，不触发 Hook、不执行 Command，也不表示当前 Session 或宿主已加载。

WorkspaceBinding 的 `value` 是 `workspaces/<workspace-id>/config.yaml` 完整规范文本，固定为 `schemaVersion: 1` 与单行 JSON `workspaceBinding`；只允许 `workspaceId / instructions / ruleIds / skillIds / mcpIds / contextPolicy / outputProfileId / outputParameterBindings / orchestrationPolicy / hookRefs / commandRefs`。`memoryRevision` 是 MemorySpace 派生只读事实，不进入普通可写 DTO、canonical 文件或 ConfigRevision 正文。Context 与 Orchestration override 必须相对 Agent 根级配置保持或收紧；根级文件缺失、损坏或局部扩大时拒绝保存。

创建尚不存在的 Binding 使用独立 `CreateWorkspaceBindingRequest { requestId, agentId, workspaceId, value }`，前端不得提交路径、assetId、cwd 或任意文件名。Local Service 从稳定 Agent/Workspace ID 推导 `agt_<agent-id>/workspaces/<workspace-id>/config.yaml`，重新验证 current v1 AgentPackage 身份、Workspace Registry canonical 目录、普通目录与符号链接边界后独占创建。已有 Binding 使用普通 SaveConfig；save、revision recovery 和 restore 均重新验证 Workspace Registry。WorkspaceBinding 是 Agent ↔ Workspace 唯一写入事实，Workspace 侧 Agent 列表和状态必须派生。

`baseContent` 必须原样携带本次 `LoadEditorResult.canonicalContent`；Local Service 先验证其哈希与 `expectedBaseline` 一致，外部变化时据此返回真实 `base / current / proposed` 三方内容。Local Service 必须确认 `assetId` 指向与 change kind 一致、可写、已解析且受支持的资产，并执行目标解析、双哈希基线复核、受限原子写入、重读验证和 ConfigRevision 记录。其他配置族即使当前 Web Mock 已有页面内存编辑，也不得复用相近分支或以 `kind: string` 绕过冻结联合；须先按本文第 14 节冻结对应 DTO 切片。

AgentPackage schema 兼容判断由 Local Service 基于已读取事实返回：current v1 可编辑；legacy、future 只读；unverified 不得被当作 v1。Instructions 保存仍须重新验证 package schema、稳定资产身份、目标路径和写权限。

配置方案、工具登记、备份、网络代理和 Plugin 安装仍不属于保存切片。工作区交接只使用第 10 节冻结的最小请求与能力事实，不映射 Gateway、Provider、凭据或宿主工具真实配置，不增加连接测试、环境变量注入、进程重启、任意安装 API 或 Plugin 执行 API。

## 7. 当前操作确认

```ts

  id: Id
  assetId: Id
  proposedContentHash: ContentHash
  expiresAt: Timestamp
  reason: string
}

  kind: 'confirmation_required'
  requestId: Id

```

Permissions challenge 绑定资产、待写内容哈希、签发时基线哈希（仅服务端持久化）和有效期，当前有效期为 10 分钟。确认后前端使用同一业务请求并附带 `confirmationRef`；Local Service 必须重新校验 challenge 未过期、资产、内容哈希和当前基线仍匹配。challenge 在成功校验时一次性消费，不能复用；若后续文件写入失败，用户须重新发起保存并取得新的 challenge。

文件权限扩大按严格等级比较：`未授予 < 只读当前工作区 < 仅当前工作区 < 任意目录`。当前页面只编辑 `files`；为避免无法证明安全的隐式扩权，`commands / network / delegation` 任意变化均保守视为扩大并要求确认。收紧不需要确认，且携带 `confirmationRef` 会被拒绝。成功扩权生成的 `ConfigRevisionDto.confirmationRefs` 必须记录 challenge ID。恢复历史版本复用相同权限比较：恢复到更宽边界先返回 `confirmation_required`，确认后才恢复为新版本。

这是当前长期配置操作的短期确认引用，不是 Approval、Task 或可复用权限；页面输入 Agent 名称与勾选理解后果只是独立 UI 确认步骤，不是跨进程授权凭据。Claude Code 中某次工具调用的一次性授权不进入本契约。

## 11. 前端状态处理

真实联调后的前端状态流固定为：

```text
页面 draft
→ SaveConfigRequest
→ saved / unchanged：更新 canonical，退出编辑
→ baseline_changed：保留 draft，展示 base/current/proposed
→ confirmation_required：保留 draft，确认后带 confirmationRef 重试
→ validation_failed：保留 draft，定位字段或文件诊断
→ save_failed：保留 draft，展示失败和是否可重试
```

不得把当前 `apps/web/src/state.tsx` 的整个 `State`、`Action` 或同步 reducer 直接变成共享协议。页面状态、对话框开关、Toast 和严格白名单的本机 `UiPreferences` 仍是前端实现细节。主题、强调色、字体、字号、密度、主菜单布局、工作台辅助名称和背景不得通过 `SaveConfigRequest` 写入 Local Service，也不生成 ConfigRevision 或 Local Service 事件。固定槽位的 Logo / 背景图片命令仅是 Tauri 桌面壳本机能力，不是业务 DTO。

### 11.1 受管 Agent 头像窄契约

首版头像只属于 Bandi Desktop 受管 AgentPackage：根目录固定保存 `avatar.png`，`agent.yaml` 仅以可选 `avatarPath: "avatar.png"` 引用。创建命令一次接收稳定 `agentId`、完整 canonical Agent、待写配置文件和可选 PNG；后端在同父目录 staging 中全部写完后再提交。身份编辑先调用 `load_managed_agent_identity(agentId)`，由服务返回稳定 identity `assetId / containerId`、真实 `canonicalContent`、locator 和双 SHA-256 `baselineRef`。身份保存命令一次接收 `requestId`、完整 canonical Agent、完整 identity manifest、服务签发的 `expectedBaseline`、原样 `baseContent`，以及 `keep | replace | remove` 头像变更；前端不提交目标目录、原文件名或任意路径。

身份保存与 Instructions 使用相同结果语义：`saved / unchanged / baseline_changed / validation_failed / save_failed`。`saved` 必须在受限原子写入、写后重读验证和 ConfigRevision（正文只记录完整 `agent.yaml`，不记录头像字节）成功后返回；revision 失败返回 `verified_written_revision_pending`。编辑期间外部变化必须返回真实 `base/current/proposed`，不提供通用 force。manifest、头像或 canonical 索引任一步写失败时必须恢复原 manifest、头像和索引记录。

头像仅接受 PNG 签名且最大 5 MiB；读取失败或缺少引用时 UI 回退姓名首字符。Desktop 启动通过只读扫描恢复受管 Agent canonical 状态。纯 Web、`external-reference`、legacy、future 和 unverified 包不得调用写命令，也不得把页面内存操作描述成磁盘保存。

8. `RequestClientHandoff`、`ClientHandoffResult`、9 个 `BuiltInClientId`、`ClientAdapterId`、`TerminalId`、`ClientHandoffIntent`；
9. `CapabilityStatus`、`CapabilityFactDto`；
10. `SharedAssetNodeDto`、`AssetReferenceDto` 与六种引用状态；
11. Organization Snapshot、正式 Memory 与本地 Backup/Restore（以 `packages/contracts/schemas/` 及共享 fixture 为 wire 事实源）；
12. `ClaudeAgentPreviewDto`、`preview_claude_agent` 与 `import_claude_agent` 单文件导入切片。

“冻结”表示 Rust、TypeScript、fixture 和合同测试必须共享同一字段与枚举；实现不得用自由字符串、`unknown`、额外 envelope 或兼容别名替代。当前未冻结的内部服务名、实时文件事件、Plugin/Skill 安装事务、远程 Git、终端安装探测、共享资产写事务及跨 Company 独立授权不得借现有 DTO 进入公开跨进程边界。

## 14. 后续 DTO 切片冻结门槛

任何其他 DTO 进入实现前，必须先在本文增加一个独立、可验收的竖切片，并同时完成：

- 明确页面入口与单一用户结果；
- 记录当前事实、目标事实和后端责任；
- 冻结请求、结果、错误/诊断和事件；
- 指定能力状态及 `reason/evidence/remediation` 来源；
- 提供 Rust ↔ TypeScript 序列化合同 fixture；
- 覆盖成功、未检查、降级、不可用、校验失败和越权输入；
- 更新[《首版能力矩阵》](./首版能力矩阵.md)中的证据、测试与缺口。

未满足上述条件时，保持页面内存演示、只读或不可用，不得通过扩大通用 DTO、加入任意 `payload` 或复用相近命令抢先施工。

## 15. 契约变更规则

- 新增可选字段必须保持旧调用方可忽略；新增联合分支必须同步前端穷尽检查。
- 修改枚举值、字段语义或必填性属于破坏性变化，必须同步更新本文、Rust DTO、TypeScript DTO、合同 fixture 和契约测试。
- 不为假设的未来客户端增加通用 envelope、Repository、SDK 或版本协商层；出现第二个真实 Adapter 且语义确有差异时再按第 14 节冻结新切片。
