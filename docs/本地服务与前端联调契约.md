# 本地服务与前端联调契约

> 文档版本：v1.1-draft
> 更新日期：2026-08-31  
> 状态：首轮跨进程契约  
> 关联文档：[《产品与页面架构》](./产品与页面架构.md) · [《技术架构》](./技术架构.md)

## 1. 范围

本文只冻结 Bandi Desktop 前端与 Rust Local Service 近期联调必需的跨进程语义：授权根内只读发现、编辑器加载、普通配置保存、外部基线变化、当前操作确认、诊断、配置失效事件、长操作进度和终端打开请求。

Local Service 内部的 `ResolveTarget`、`ValidateEdit`、`RestrictedConfigWriter` 等名称不是 wire API。传输可使用 Tauri Command 或受限 localhost API，但不得因此改变本文 DTO 的业务语义。

本契约不包含：

- Task、WorkflowRun、Assignment、Handoff 或执行期 Approval；
- 一次性工具权限持久化；
- Session 创建、attach、停止、恢复或跟踪；
- 聊天、Todo、工具调用、日志、Usage 或 Agent View 镜像；
- Desktop SOP 执行器；
- 多 AI 客户端 Adapter、统一客户端协议、Provider、Model、账户或 Quota；
- Plugin / MCP 直接写 SQLite、AgentPackage 或正式 Memory；
- 任意 Shell API；
- 首轮远程 Git、多设备同步或自动冲突合并协议。

## 2. 通用序列化规则

```ts
type Id = string
type Timestamp = string // RFC 3339 UTC，例如 2026-08-31T10:42:00Z
type ContentHash = `sha256:${string}`
type RelativeAssetPath = string
type AbsoluteSystemPath = string
type RootKind = 'workspace' | 'claude_user' | 'managed' | 'bandi' | 'authorized_external'
type OfficialScope = 'user' | 'project' | 'local' | 'managed' | 'bandi'
```

- JSON 字段使用 `camelCase`，枚举值使用稳定 ASCII `snake_case`。
- 持久化对象 ID 由 Local Service 生成且对调用方不透明；`requestId` 由调用方生成，只用于幂等和关联。
- 时间统一传 RFC 3339 UTC，不传“刚刚”“昨天”等展示文本。
- 内容哈希必须携带算法前缀。
- 写操作以稳定 `assetId` 定位。AgentPackage 内路径使用不含 `..` 的规范相对路径；绝对路径由 Local Service 返回和校验，`~` 只用于 UI 展示。
- 字段缺失表示“未提供”；`null` 仅用于 Schema 明确允许的清除语义；空字符串是实际值，不与前两者混用。
- 前端不得根据中文文案判断业务分支，只判断 `kind`、`code` 等稳定字段。
- secret 必须在 Local Service 内脱敏；前端 DTO 不传 secret 原文，不能用 CSS 隐藏代替脱敏。

## 3. 资产定位、发现与编辑器加载

```ts
type AssetLocatorDto = {
  rootKind: RootKind
  displayPath: string
  relativePath?: RelativeAssetPath
}

type SourceContainerDto = {
  id: Id
  locator: AssetLocatorDto
  format: 'json' | 'jsonc' | 'yaml' | 'toml' | 'markdown' | 'directory'
  contentHash: ContentHash
  writable: boolean
  readOnlyReason?: string
}

type SourceAssetSummaryDto = {
  id: Id
  containerId: Id
  kind: string
  officialScope: OfficialScope
  fragment?: string
  workspaceId?: Id
  companyId?: Id
  assetContentHash: ContentHash
  containerContentHash: ContentHash
  writable: boolean
  parseStatus: 'parsed' | 'invalid' | 'unsupported' | 'redacted'
  diagnostics: Diagnostic[]
}

type DiscoveryRequest = {
  requestId: Id
  workspaceIds: Id[]
  includeClaudeUserRoot: boolean
}

type DiscoveryResult = {
  requestId: Id
  profileVersion: string
  containers: SourceContainerDto[]
  assets: SourceAssetSummaryDto[]
  diagnostics: Diagnostic[]
}

type BaselineRefDto = {
  id: Id
  assetId: Id
  containerId: Id
  assetContentHash: ContentHash
  containerContentHash: ContentHash
}

type LoadEditorRequest = { requestId: Id; assetId: Id }

type LoadEditorResult = {
  requestId: Id
  asset: SourceAssetSummaryDto
  canonicalContent: string
  redacted: boolean
  baselineRef: BaselineRefDto
  diagnostics: Diagnostic[]
}
```

发现只读取已经登记和授权的 Workspace、Claude 用户配置根及明确授权外部根，不导入、不安装、不改写文件。用户配置根从 `CLAUDE_CONFIG_DIR` 或 Claude Code 默认规则解析；项目配置只在目标 Workspace 下发现。`managed` 和 Plugin cache 可作为只读证据，但 cache 不成为普通资产或恢复目标。

`SourceContainerDto` 表示物理文件/目录；`SourceAssetSummaryDto` 表示其中逻辑 fragment。一个 container 可以有多个 asset。前端保存只能提交稳定 `assetId` 与服务签发的 `baselineRef`，不能提交任意绝对写入路径。

## 4. 基础诊断

```ts
type Diagnostic = {
  code: string
  severity: 'error' | 'warning' | 'info'
  message: string
  field?: string
  path?: RelativeAssetPath
  range?: {
    startLine: number
    startColumn: number
    endLine: number
    endColumn: number
  }
  remediation?: string
}
```

`code` 是行为判断依据，`message` 是可直接展示的本地化文本。前端必须能通用展示未知 `code`，不能因未知诊断而丢失错误信息。字段级错误尽量提供 `field`，原文错误尽量提供 `path` 和 `range`。首轮新增语义应使用稳定 code family 覆盖 package legacy/future/unverified、manifest 无效、Role 缺失/作用域不匹配、Orchestration 非法/扩权/有环、Hook/Command/OutputProfile kind 或引用错误、Plugin 不完整/不兼容和 parameter binding 无效；具体字符串在实现 Local Service schema 时冻结，前端不得从中文 message 反推分支。

## 5. 普通配置保存

### 5.1 请求

现有前端 `apps/web/src/agent-config-model.ts` 的 `AgentConfigPayload` 可继续作为页面内判别联合思路，但不能直接作为 wire DTO。跨进程请求必须包含目标资产和编辑基线。

```ts
type ConfigChange =
  | { kind: 'identity'; value: AgentManifestConfigDto }
  | { kind: 'instructions'; value: string }
  | { kind: 'context_policy'; value: AgentContextConfigDto }
  | { kind: 'skills'; value: ComponentReferenceDto[] }
  | { kind: 'rules'; value: ComponentReferenceDto[] }
  | { kind: 'mcp'; value: ComponentReferenceDto[] }
  | { kind: 'permissions'; value: AgentPermissionsDto }
  | { kind: 'sop'; value: ComponentReferenceDto[] }
  | { kind: 'orchestration'; value: OrchestrationPolicyDto }
  | { kind: 'hooks'; value: ComponentReferenceDto[] }
  | { kind: 'commands'; value: ComponentReferenceDto[] }
  | { kind: 'workspace_binding'; value: WorkspaceBindingDto }

type SaveConfigRequest = {
  requestId: Id
  assetId: Id
  change: ConfigChange
  expectedBaseline: BaselineRefDto
  confirmationRef?: Id
}
```

`identity` 必须携带完整 v1 manifest，包括 `schemaVersion: 1`、稳定 Agent ID、`roleId`、ASCII lifecycle 和完整职责字段，不接受只修改 lifecycle 的局部 wire payload。`context_policy` 只承载 Agent 根级上下文压缩长期策略、OutputProfile ID 与其类型化参数绑定；当前 token、压缩次数、摘要正文及 Session 是否加载配置不属于该 DTO。`workspace_binding` 可携带局部策略、OutputProfile/参数覆盖、Hook/Command 显式引用和只能收紧的 Orchestration override，其中 Memory revision 只能作为只读观察字段或由 Local Service 忽略；普通 WorkspaceBinding 保存不得创建、推进或覆盖正式 Memory revision。

`ComponentReferenceDto` 只能绑定已登记的可信资产及五种非敏感参数（string、number、boolean、string-list、enum）；不得携带脚本、Shell、可执行程序、cwd、环境变量、文件落点、任意 object 或 secret。Hook/Command 保存只管理定义引用，不触发执行。OutputProfile destination 固定为 response，不提供文件、网络、Webhook 或其他外部投递 DTO。

AgentPackage schema 兼容判断由 Local Service 基于已读取事实返回：current v1 可编辑；legacy、future 只读；unverified 不得被当作 v1。保存和恢复都必须重新验证 schema、稳定 ID、Role 作用域、资产 kind、Plugin 组件兼容性、参数、Workspace 编排收紧和权限边界。

配置方案、工具登记、备份、网络代理、Plugin 安装/探测和客户端 Adapter 尚不属于本轮跨进程契约。当前 Web Mock 仅在 React 页面内存演示这些选择；配置方案只记录名称和已加入工具，单方案版本使用页面内存 `ConfigRevision`，“全部配置”快照也只描述 Bandi 自有方案元数据，不映射或备份 Gateway、Provider、凭据或宿主工具真实配置，网络代理同样不读取或应用系统设置。本轮界面归并不新增 DTO、command 或 event。不得据此增加连接测试、环境变量注入、进程重启、真实凭据 DTO、任意安装 API 或 Plugin 执行 API；未来接入时必须另行设计最小权限协议。

### 5.2 结果

```ts
type SaveConfigResult =
  | Saved
  | Unchanged
  | BaselineChanged
  | ConfirmationRequired
  | ValidationFailed
  | SaveFailed

type WriteReceiptDto = {
  id: Id
  containerId: Id
  previousContainerHash: ContentHash
  writtenContainerHash: ContentHash
  verifiedAt: Timestamp
  atomicReplace: boolean
}

type Saved = {
  kind: 'saved'
  requestId: Id
  asset: SourceAssetSummaryDto
  revision: ConfigRevisionDto
  writeReceipt: WriteReceiptDto
}

type Unchanged = {
  kind: 'unchanged'
  requestId: Id
  asset: SourceAssetSummaryDto
}

type ValidationFailed = {
  kind: 'validation_failed'
  requestId: Id
  diagnostics: Diagnostic[]
}

type SaveFailed = {
  kind: 'save_failed'
  requestId: Id
  diagnostics: Diagnostic[]
  retryable: boolean
  fileState: 'unchanged' | 'write_not_verified' | 'verified_written_revision_pending'
  recoveryRef?: Id
}
```

只有写入、重读验证和 ConfigRevision 记录都成功，才能返回 `saved`。内容无变化返回 `unchanged`，不生成 revision。前端只有收到 `saved` 或 `unchanged` 才更新 canonical 状态并退出编辑；其余结果必须保留 draft。

前端只调用一次类型化保存请求。Local Service 内部的目标解析、基线加载、校验、基线复核、原子写入、重读验证和 revision 记录不得扩张为前端逐步调用的向导或事件状态机。

## 6. 外部基线变化

```ts
type ConfigSide = {
  content: string
  assetContentHash: ContentHash
  containerContentHash: ContentHash
  redacted: boolean
  revisionId?: Id
}

type BaselineChanged = {
  kind: 'baseline_changed'
  requestId: Id
  assetId: Id
  containerId: Id
  fragment?: string
  locator: AssetLocatorDto
  base: ConfigSide
  current: ConfigSide
  proposed: ConfigSide
  diagnostics: Diagnostic[]
}
```

- `base` 是前端开始编辑时的内容，`current` 是 Local Service 重新读取的当前内容，`proposed` 是用户待保存内容。
- Local Service 不接受通用 `force` 绕过基线检查。
- 用户放弃、复制自己的编辑或基于 current 重新应用后，前端必须重新加载服务签发的 `baselineRef` 再提交；不能只替换一个 hash。
- 只有无法安全自动合并的同字段或同文本区域变化才称为配置文件冲突；普通外部变化先展示三方内容。

## 7. 当前操作确认

```ts
type ConfirmationReason =
  | 'permission_expansion'
  | 'shared_impact'
  | 'restore'
  | 'destructive_change'

type ConfirmationChallenge = {
  id: Id
  reason: ConfirmationReason
  title: string
  summary: string
  consequences: string[]
  boundAssetId: Id
  boundContentHash: ContentHash
  expiresAt: Timestamp
}

type ConfirmationRequired = {
  kind: 'confirmation_required'
  requestId: Id
  challenge: ConfirmationChallenge
  diagnostics: Diagnostic[]
}
```

challenge 绑定资产、待写内容哈希和有效期。确认后前端使用同一业务请求并附带 `confirmationRef`；Local Service 必须重新校验 challenge 未过期、资产和内容哈希仍匹配、当前基线未变化。旧确认不得授权新的内容。

这是当前长期配置操作的短期确认引用，不是 Approval、Task 或可复用权限。长期权限收紧不需要 `permission_expansion` 确认；Claude Code 中某次工具调用的一次性授权不进入本契约。

### 8.1 Plugin 安装事实

```ts
type PluginInstallationDto = {
  pluginId: Id
  officialScope: 'user' | 'project' | 'local' | 'managed'
  installed: boolean
  enabled: boolean
  installedVersion?: string
  compatible: boolean
  componentsComplete: boolean

```

Company 不进入 `officialScope`；它只通过资产治理关系表达。`cache_only` 不得推断 installed、enabled 或当前 Session loaded，且 cache 不是普通写回和恢复目标。安装、启用、引用和 Session loaded 必须分别建模。

## 9. Local Service 事件

```ts
type LocalServiceEvent =
  | ConfigInvalidatedEvent
  | OperationProgressEvent

type ConfigInvalidatedEvent = {
  kind: 'config_invalidated'
  eventId: Id
  occurredAt: Timestamp
  assetIds: Id[]
  reason: 'external_change' | 'discovery_changed' | 'parser_changed'
}

type OperationProgressEvent = {
  kind: 'operation_progress'
  eventId: Id
  occurredAt: Timestamp
  operationId: Id
  operationKind: 'discovery' | 'backup' | 'restore'
  phase: string
  completed: number
  total?: number
  message?: string
}
```

- 配置失效事件只通知前端重新查询，不携带未经重读验证的完整事实。
- 进度事件只用于明显长操作；普通单文件保存直接返回结果。
- `phase` 只用于显示，不驱动业务状态机。操作最终结果必须由对应请求返回或查询取得。
- 不发布 Session、Agent 运行、任务、审批、工具调用、Todo 或日志事件。

如果备份尚未进入首轮实现，`backup` / `restore` 只是保留的枚举语义，不要求当前后端提供对应命令或事件。

## 10. 结构化终端启动

```ts
type TerminalId =
  | 'terminal'
  | 'iterm2'
  | 'warp'
  | 'ghostty'
  | 'wezterm'
  | 'kitty'
  | 'alacritty'

type LaunchWorkspaceRequest = {
  requestId: Id
  workspaceId: Id
  cwd: AbsoluteSystemPath
  terminalId: TerminalId
  executable: string
  args: string[]
  enterBandiOnStart: boolean
}

type LaunchWorkspaceResult =
  | { kind: 'accepted'; requestId: Id; acceptedAt: Timestamp }
  | {
      kind: 'fallback-required'
      requestId: Id
      executable: string
      args: string[]
      message: string
    }
  | { kind: 'rejected'; requestId: Id; code: string; message: string }
```

终端 ID 到应用标识和系统参数的映射完全由后端白名单持有。前端只能传配置方案中的结构化 executable 与独立 argv，不得传 bundle ID、Shell 字符串、环境变量、stdin 或脚本正文。Rust 校验命令名或绝对可执行文件、参数数量与长度，并根据 `enterBandiOnStart` 固定追加一次 `/bandi:bandi`，不调用 Shell。当前最小 Tauri 壳对 `cwd` 执行绝对路径、存在性、目录和 canonicalize 校验；Local Service 建立持久化 Workspace registry 后，必须进一步根据 `workspaceId` 重取登记路径并验证一致性。

Ghostty、WezTerm、Kitty、Alacritty 可通过各自 CLI 传递 cwd 与 argv。Terminal.app、iTerm2、Warp 及本机未安装或未完成真实验证的终端返回 `fallback-required`：后端只打开 cwd，前端保留 Dialog 并提供完整命令复制。`accepted` 仅表示操作系统接受了启动请求，不表示 Claude Code、`/bandi:bandi` 或 Session 已创建、连接、运行或加载，也不返回 `sessionId`、PID 或终端输出。

## 11. 前端状态处理

真实联调后的前端状态流固定为：

```text
页面 draft
→ SaveConfigRequest
→ saved / unchanged：更新 canonical，退出编辑
→ baseline_changed：保留 draft，展示 base/current/proposed
→ confirmation_required：保留 draft，确认后带 confirmationRef 重试
→ validation_failed：保留 draft，定位字段或文件诊断
→ save_failed：保留 draft，展示失败和是否可重试
```

不得把当前 `apps/web/src/state.tsx` 的整个 `State`、`Action` 或同步 reducer 直接变成共享协议。页面状态、对话框开关、Toast 和严格白名单的本机 `UiPreferences` 仍是前端实现细节。主题、强调色、字体、字号、密度、主菜单布局、工作台辅助名称和背景不得通过 `SaveConfigRequest` 写入 Local Service，也不生成 ConfigRevision 或 Local Service 事件。固定槽位的 Logo / 背景图片命令仅是 Tauri 桌面壳本机能力，不是业务 DTO。

### 11.1 受管 Agent 头像窄契约

首版头像只属于 Bandi Desktop 受管 AgentPackage：根目录固定保存 `avatar.png`，`agent.yaml` 仅以可选 `avatarPath: "avatar.png"` 引用。创建命令一次接收稳定 `agentId`、完整 canonical Agent、待写配置文件和可选 PNG；后端在同父目录 staging 中全部写完后再提交。身份保存命令一次接收完整 identity manifest、预期 manifest baseline，以及 `keep | replace | remove` 头像变更；任一步失败必须恢复原 manifest、头像和 canonical 记录。前端不提交目标目录、原文件名或任意路径。

头像仅接受 PNG 签名且最大 5 MiB；读取失败或缺少引用时 UI 回退姓名首字符。Desktop 启动通过只读扫描恢复受管 Agent canonical 状态。纯 Web、`external-reference`、legacy、future 和 unverified 包不得调用写命令，也不得把页面内存操作描述成磁盘保存。

## 12. 首轮联调场景矩阵

| 场景 | 请求 / 事件 | 期望结果 | 前端行为 |
| --- | --- | --- | --- |
| 只读发现 | 授权 Workspace 与 Claude 用户配置根 | containers + assets + diagnostics | 展示真实 scope/fragment/只读原因，不导入或改写 |
| 加载编辑器 | 可编辑 assetId | canonicalContent + 双 hash baselineRef | secret 已脱敏，保存沿用 baselineRef |
| 正常保存 | 正确 assetId、baselineRef 和合法 change | `saved` + revision + writeReceipt | 更新 canonical，退出编辑，显示目标文件和版本 |
| 内容未变化 | change 与当前语义一致 | `unchanged` | 更新 canonical，退出编辑，不显示新版本 |
| 字段或格式非法 | 非法 change | `validation_failed` | 保留 draft，在字段或文件位置展示诊断 |
| 编辑期间被外部修改 | expected hash 与当前不同 | `baseline_changed` + base/current/proposed | 保留 draft，禁止静默覆盖 |
| 扩大长期权限 | 新权限超出当前边界 | `confirmation_required` | 展示前后边界和后果；确认后重试 |
| 使用旧确认 | challenge 过期、内容或基线变化 | `confirmation_required` 或 `validation_failed` | 保留 draft，重新确认，不复用旧引用 |
| 写入或写后验证失败 | 文件系统、解析或 revision 失败 | `save_failed` + fileState | 保留 draft；若文件已验证写入但 revision 待恢复，明确显示恢复状态 |
| 外部文件变化 | `config_invalidated` | 相关资产缓存失效 | 未编辑时重载；编辑中重新检查基线 |
| 请求打开 Claude Code | 受信 cwd + argv | `accepted` 或 `rejected` | accepted 只显示请求已接受，不显示 Session 状态 |
| 备份演示 | 当前 Web Mock 页面操作 | 不调用 Local Service | 始终标记演示；不宣称创建或恢复文件 |
| 修改个性化 | `UiPreferences` 与固定 Logo / 背景槽位 | 不调用 Local Service；仅本机 UI 存储与 Tauri 窄命令 | 不影响 Agent、Workspace、配置版本、备份或 RuntimeProjection |

## 13. 契约变更规则

- 新增可选字段必须保持旧调用方可忽略；新增联合分支必须同步前端穷尽检查。
- 修改枚举值、字段语义或必填性属于破坏性变化，必须同步更新本文、Rust DTO、TypeScript DTO 和契约测试。
- 不为假设的未来客户端增加通用 envelope、Repository、SDK 或版本协商层；出现第二个真实传输消费者且语义确有差异时再评估。
