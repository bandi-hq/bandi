# 首版验收报告

> 更新日期：2026-09-01
> 范围：Bandi Desktop 本地配置管理闭环

## 1. 验收结论

当前首版已形成可构建、可诊断、可追溯的本地配置管理闭环。Desktop 已接入 Agent 全配置族、Workspace/Organization、ConfigRevision、四类正式 Memory、本地 Backup/Restore、共享资产只读引用图、AI 工具安全目录交接、`bandi` CLI 与 Bandi Plugin 只读入口。隔离数据目录的真实 Tauri WebView 自动化已验证“全新启动无演示事实”和“退出后以相同数据目录重启”；完整新增 Workspace、组织、Agent、Binding、配置与 Memory 的 UI 旅程仍由领域/页面自动测试和第 6 节人工脚本共同覆盖，不能把首条 WebView smoke 扩大表述为完整安装包验收。

以下边界仍然成立：Desktop 不创建或管理 Task、Session、Chat、Todo、运行日志、人员调度、执行审批或 SOP 运行流程；不提供通用 Shell、任意 executable/argv、凭据采集或 AI 工具自动启动。

## 4. 故障与安全场景证据

自动测试已覆盖：

- 授权根、目标文件和中间目录符号链接拒绝；
- 路径逃逸、非法稳定 ID、kind 不匹配和未知字段拒绝；
- 编辑期间外部变化与旧 baseline 拒绝；
- 原子写、重读验证、Revision 写入失败和 pending recovery；
- Permissions 扩权、过期/错配/复用 challenge 拒绝；
- Workspace Registry 缺失、身份不一致和 override 扩大拒绝；
- Organization 部门环、跨 Company 父级、主管/责任关系约束；
- Memory 自审拒绝、改投空间重验、正式文件外部变化和 revision 恢复；
- Backup 损坏内容、symlink、stale preview、恢复前安全快照和 baseline changed；快照仅覆盖 discovery 当前发现并由用户选择的可写受管配置文件，不包含 Company、Department、Role、Workspace Registry、ServiceGrant、领域数据库或当前 discovery 未纳入的正式 Memory 文件；
- 共享资产根缺失、manifest/正文无效、symlink、本体缺失、类型错误、Company 越界和无效目标；
- 未验证或错配 AI Adapter 不触发外部动作。

## 5. 数据迁移与回滚

- SQLite 使用版本化 migration 和 WAL；已有 v2/v4 数据库升级到当前 schema 的测试通过。
- 真实配置文件始终是配置正文主源；SQLite 不取代 AgentPackage 或 Workspace 文件。
- 旧 Workspace Registry 可兼容导入 SQLite；Registry canonical path 仍在每次相关写入时复核。
- 普通配置恢复生成新 ConfigRevision，不覆盖旧历史。
- 正式 Memory 恢复只补记或生成新 revision，不绕过审核事实。
- Backup 恢复前创建当前状态安全快照；失败按条目报告，不伪装全局原子事务。
- Workspace 创建通过单一 command 协调 Registry 与 SQLite：同 ID 不同路径拒绝，SQLite 保存失败时仅撤销本次新建 Registry；移除失败会补偿恢复 SQLite。普通路径 lookup 不再从残留 Registry 隐式导入或复活已删除 Workspace。
- AgentPackage 与 Organization SQLite 之间仍不承诺跨存储事务；失败后按各自事实源重载并重试未完成部分。

## 6. 用户验收脚本

1. 启动 Desktop：`pnpm desktop:dev`。
2. 新建或登记一个 Workspace，确认取消选择不会产生记录，成功后重启仍可看到。
3. 创建受管 Agent，打开 Instructions，修改并保存；确认出现真实版本记录。
4. 再次保存相同内容，确认不新增版本；从外部修改目标文件后重试保存，确认出现三方差异而非静默覆盖。
5. 分别打开 Context、Rules、Skills、MCP、Permissions、SOP、Orchestration、Hooks、Commands；保存一个合法变化。Permissions 扩大时确认必须出现独立确认。
6. 为 Agent 创建 Workspace 专属配置，确认 Workspace 侧关系由 Binding 派生，不能写入 `memoryRevision`。
7. 在组织页创建 Company、Department、Role 和 ServiceGrant；尝试制造部门环或跨 Company 关系，确认被拒绝。
8. 在正式 Memory 入口提交候选，由不同审核者批准；分别检查 Agent 长期、Agent × Workspace、Workspace 公共和 Department × Workspace 历史。
9. 在设置的配置与备份中创建本地快照，打开恢复预览，确认影响后恢复；检查恢复前安全快照与新 ConfigRevision。
10. 在资产页查看配置资产与共享资产节点；确认共享节点显示反向引用，异常引用按缺失、类型、越界或无效目标区分。
11. 在 AI 工具入口选择 Claude Code 或 Codex 和已登记 Workspace；确认系统只打开目录，不自动启动工具、输入命令或显示 Session 状态。
12. 在终端运行 `pnpm cli doctor`、`pnpm cli status`、`pnpm cli config check`，核对输出与当前本机事实一致。
13. 切换亮/暗主题，并在宽屏与窄屏检查 Agents、组织、工作区、资产和设置；用 Tab、Shift+Tab、Escape 操作 Dialog/Sheet，确认焦点可见且关闭后回到合理触发点。

## 7. 明确开放项

- 共享资产当前只读；没有创建、编辑、删除、安装或执行事务。
- 跨 Company 共享资产的独立注册与授权模型尚未实现；当前越界引用为 `out_of_scope`。
- 实时 `LocalServiceEvent` 文件监听尚未实现；安全写入依靠每次请求前重读与双哈希 baseline。
- Skill/Plugin 安装、更新、回滚、卸载仍是明确演示/未冻结能力。
- 远程 Private Git 备份、多设备同步和正式 Memory 远程备份尚未实现。
- Gemini CLI、OpenCode、OpenClaw、Hermes、Pi 的 Workspace 交接仍为 `not_checked`；Claude Desktop 和 Grok Build 为已确认 `unavailable`。
- Vite 主 chunk 超过默认 500 kB 警告线；不影响当前正确性，但后续可按路由拆包。
- `tauri.conf.json` 仍为 `bundle.active: false`；当前未验证安装器、签名、首次安装、升级、卸载与残留清理，不能宣称“安装包首次安装已通过”。
- 当前真实 Tauri E2E 只覆盖首次空状态和相同数据目录重启；完整新增 Workspace、Company、Department、Role、两个 Agent、Binding、配置、Memory 和 Backup 的 WebView 自动旅程尚未落地，第 6 节仍需人工执行。
