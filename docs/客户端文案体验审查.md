# Bandi 客户端文案体验审查

> 审查基线：2026-09-03 当前工作树（含未提交改动）  
> 方法：项目级 `product-content-strategist` Skill + 路由 × 状态 × 来源 × 文案表面交叉审查  
> 交付边界：本报告提出优化方案，不修改应用运行时代码或测试。

## 1. 执行摘要

Bandi 当前文案总体准确、克制，且对 Desktop 与 Browser 演示、配置管理与任务执行的边界有较强安全意识。主要问题不是“语气不好”，而是**实现模型进入了默认用户界面**：用户需要先理解 `AgentPackage`、`WorkspaceBinding`、`ConfigRevision`、基线、来源边、WAL 等内部概念，才能判断下一步该做什么。

本轮审查覆盖当前路由中的应用壳、概览、Agent、组织、工作区、资产、设置、使用引导、404 与路由错误，同时抽查了前端状态通知、展示 helper、DTO 和 Rust/Tauri 动态错误。共识别 **3 项 P0、22 项 P1、14 项 P2、3 项 P3**。最高优先级不是润色，而是：

1. 修复工作区“配置状态”筛选显示值与真实状态不一致的问题；
2. 修复资产诊断因显示路径而隐藏问题内容的问题；
3. 为永久删除的部分完成状态提供准确反馈，避免用户重复删除；
4. 建立统一的用户错误层，停止直接展示 Rust/Tauri 原始错误；
5. 将 AgentPackage 等实现术语降到“技术详情”；
6. 让按钮准确说明动作结果，尤其是导入、登记、删除、恢复和工具方案操作；
7. 高风险确认保留不可逆性、清理范围、保留内容和重新检查机制，不以“简短”为由删减事实。

一句话内容原则：

> **默认界面说用户任务；风险确认说实际影响；技术详情说证据。**

## 2. 审查范围与方法

### 2.1 已覆盖入口

对照 `apps/web/src/router.tsx:21-38`，已覆盖：

- 配置概览与首次使用；
- Agent 列表、创建、导入、外部登记、配置详情、原始文件、正式记忆和危险区；
- 组织、公司、部门、岗位和服务授权；
- 工作区列表、向导、详情和项目责任；
- 资产发现、详情、Skill、Plugin 和 SOP；
- 设置、工具方案、个性化、快照恢复和恢复出厂；
- 使用引导、404、路由错误和全局通知。

### 2.2 已覆盖状态

按页面抽查默认、加载、空态、筛选无结果、成功、校验失败、系统失败、只读、外部变化、恢复待补记、权限边界、危险确认，以及 Browser 演示与 Desktop 两套能力分支。

### 2.3 已覆盖来源

- React 页面、共享组件、按钮、标题、字段、帮助、placeholder、`aria-label`、live region；
- `state.tsx` 中的全局通知；
- `presentation.ts`、selector、policy、projection 和 adapter 中的动态展示文本；
- DTO 中的诊断、补救、删除影响和确认文字；
- Rust/Tauri 的 `Err(String)`、diagnostic、capability reason/remediation 和恢复结果。

测试中的文字断言只作为现有契约证据，不作为产品事实来源。

### 2.4 三问门槛

每条建议至少满足以下一项，否则保留原文：

1. 当前文案违反明确内容规则；
2. 术语、歧义、缺少条件或缺少结果会使用户困惑；
3. 文案隐藏或错误描述真实行为。

## 3. Bandi Voice Chart

| 场景 | 用户此刻需要 | 语气 | 应该这样写 | 避免 |
|---|---|---|---|---|
| 首次使用 | 明白产品价值和第一步 | 清楚、从容 | 先说“导入或创建 Agent”，再说明安全边界 | 一开始解释目录结构和内部模型 |
| 日常配置 | 快速完成查看、修改、保存 | 直接、克制 | 动词 + 对象；结果与按钮一致 | 重复产品边界、泛泛的“保存” |
| 成功反馈 | 确认结果和影响范围 | 简短、确定 | “主指令已保存”“只更新当前页面” | “成功地完成了……” |
| 错误恢复 | 知道什么没完成、为何、怎么办 | 冷静、具体 | “无法保存主指令。文件已在外部变化，请重新载入后比较。” | 原始错误码、责备用户、只有“无效” |
| 外部变化 | 避免误覆盖并保留用户输入 | 审慎 | 说明当前文件已变化、不会自动覆盖、下一步 | 只说“基线冲突” |
| 删除/恢复 | 理解范围、不可逆性和保留项 | 严肃、无修辞 | 明列会删除、会保留、阻塞项和再次校验 | 为了简短省略事实；“确定吗？” |
| Desktop/Browser | 判断操作是否真实生效 | 明确、不含糊 | Desktop 说真实落盘；Browser 说仅当前页面 | 用同一个按钮或成功文案伪装等价能力 |
| Claude Code 交接 | 知道回到哪里继续任务 | 务实 | “回到 Claude Code 使用” | 暗示 Bandi 启动任务、会话或终端 |
| 技术详情 | 为排障提供证据 | 精确、可复制 | 错误码、ID、路径、哈希放可展开区域 | 把诊断详情作为主文案 |

Bandi 的稳定 Voice：**可靠、克制、清楚、安全审慎、不越权**。Tone 随风险升高而更直接，但不变得生硬或责备用户。

## 4. 术语分层

| 层级 | 术语 | 使用规则 |
|---|---|---|
| 可直接使用 | Agent、Claude Code、MCP、SOP、Skill、Plugin | 目标用户日常使用；保持大小写和产品内一致 |
| 默认用户层 | Agent 配置、受管配置、工作区专属配置、配置版本、记忆修改建议、当前文件、外部修改、本地快照 | 页面标题、按钮、空态、通知和主错误优先使用 |
| 仅技术详情 | AgentPackage、WorkspaceBinding、ConfigRevision、MemoryCandidate、baseline/基线、来源边、反向引用、WAL/SHM、哈希、schema、requestId、诊断 code | 只在原始文件、开发者证据、可展开技术详情中出现 |

### 展示层建议

`apps/web/src/presentation.ts:30-40` 已集中处理部分领域词，但当前 `localizeDomainText()` 对任意文本执行 `replaceAll`。这只能作为过渡兜底，不能成为最终文案架构：它可能误改路径、用户输入或不同语境中的同名文本。建议继续复用明确的 label map；错误则按错误码或结果类型映射，不做全文替换。`memoryScopeLabel()` 和 `assetKindLabel()` 的未知值回显也应只出现在技术详情，默认层使用“未知记忆范围”“未知资产类型”。

## 6. 动态与后端文案：必须按链路治理

### 6.1 当前链路

```text
Rust service 生成 Err / Diagnostic / impact / confirmationText
  → Tauri command 与 DTO
  → contracts.ts / desktop-bridge.ts
  → state、页面或对话框
  → 用户看到主错误、通知或风险确认
```

代表性来源包括：

- `apps/desktop/src-tauri/src/agent_service.rs:253-425`：`Agent commit operation`、删除操作状态等协议错误；
- `apps/desktop/src-tauri/src/lib.rs:941-1396`：`AgentPackage`、错误码、schema 与只读原因；
- `apps/desktop/src-tauri/src/local_service.rs:2774-2893`：`ConfigRevision` 目录、身份和完整性错误；
- `apps/desktop/src-tauri/src/memory_target.rs:191-203,418,567`：`WorkspaceBinding` 检查与失效；
- `apps/desktop/src-tauri/src/factory_reset.rs:171-256`：恢复出厂确认和预览错误；
- `apps/web/src/state.tsx:946` 及多处页面 catch：原始异常进入 notice 或 inline alert。

### 6.2 建议的四层错误模型

1. **用户动作未完成**：`无法保存主指令`；
2. **可理解原因**：`文件已在其他位置修改`；
3. **下一步**：`重新载入后比较你的修改`；
4. **技术详情**：错误码、原始诊断、路径、ID、阶段和可复制证据。

示例：

```text
无法保存主指令
文件已在外部修改。重新载入后比较你的修改；Bandi 不会自动覆盖当前文件。

技术详情
BASELINE_CHANGED · asset=… · path=…
```

### 6.3 归属规则

| 内容 | 最佳归属 | 原因 |
|---|---|---|
| 稳定名词、状态、资产类型、记忆范围 | `presentation.ts` 的显式映射 | 多页面一致、可测试 |
| 动作是否完成、行为事实、影响清单 | Rust/Tauri 结构化结果 | 后端最了解真实行为 |
| 面向页面的主错误和下一步 | 前端按结果类型映射 | 需要结合当前用户动作和页面入口 |
| 错误码、路径、哈希、阶段 | 折叠技术详情 | 用于诊断，不是主任务 |

不要把后端错误全部改成更口语的字符串后继续透传；那仍然把产品内容绑定在协议异常上。优先让后端返回稳定 code/typed result，前端按动作提供主文案，原始 message 只作为证据。

## 7. 高风险流程专项

### 7.1 永久删除 Agent

`apps/web/src/pages/agents/agent-danger-zone.tsx:160-186` 已包含重要事实：删除受管配置和版本、独立备份仍可能保留副本、操作不是隐私擦除、预览会过期、提交时再次检查。这些内容应保留。优化重点仅是把默认标题的 `AgentPackage` 改为“Agent”，并把原始错误分层。

后端 `apps/desktop/src-tauri/src/lib.rs:2111` 生成确认文字“永久删除 {name}”，前端严格匹配 `preview.confirmationText`。如改确认短语，必须前后端与测试同步，不能单改界面。

### 7.2 快照恢复

`apps/web/src/pages/settings/desktop-backup-panel.tsx:175,180` 对凭据、私钥、当前版本校验、部分失败和恢复前安全快照的说明都是必要事实。建议折叠信息而不是删除。尤其不要把“可回退”写成“可完整恢复”：当前快照不覆盖组织领域数据和正式记忆。

### 7.3 恢复出厂

默认清单应按用户数据类别合并，但完整技术目标必须可展开。提交后要求立即重启、当前窗口不应继续编辑的提示应保持高可见性。确认文字虽然可能短，但真正的安全门槛还包括服务端预览、`previewRef`、目标变化校验和 `canCommit`；文案不能暗示输入一句“确认”就是唯一保护。

### 7.4 外部变化

统一使用：

```text
当前文件已在外部修改
Bandi 不会自动覆盖。重新载入后比较当前文件、原始内容和你的修改。
```

不要只说“基线变化”；也不要在重新载入会丢草稿时遗漏这一事实。

### 7.5 长期权限与组织关系

继续保留“组织身份、主管关系和服务授权不会自动授予文件、命令或网络权限”。该事实是 Bandi 产品边界，不是可删的重复免责声明。优化方式是把它放在首次设置、高影响变更和权限页，而不是每个普通保存反馈都重复完整句子。

## 8. Browser 与 Desktop 能力边界

### 应保留的表达

- Browser：更改只在当前页面有效，刷新恢复，不读取或写入本机文件；
- Desktop：只对用户通过系统选择器或已登记边界明确授权的对象操作；
- 资产“被发现”不等于已安装、已连接或当前会话已加载；
- Bandi 管理长期配置，任务执行、协作和验收仍在 Claude Code 中完成。

### 应优化的表达方式

1. **按钮本身就区分真实结果**：Browser 使用“添加演示工作区”“保存到当前页面”；Desktop 使用“添加工作区”“保存配置”。
2. **不要靠页尾长免责声明补救错误按钮**：例如 Desktop 的 aria 名仍称“演示索引”，应直接修正控件文案。
3. **边界就近出现一次**：首次进入或执行可能被误解的动作时展示；普通浏览不重复整段。
4. **不虚构下一步**：未接入移动部门、安装插件、运行命令等能力时，不写“前往某处完成”。

## 10. 分批落地顺序

### 批次 A：正确性与风险（P0 + 高风险 P1）

- 修复工作区筛选值；
- 修复资产诊断隐藏问题内容的渲染逻辑；
- 按删除阶段准确呈现“部分完成、仍待清理”，防止重复删除；
- 更换公司确认补充实际清空项；
- 删除、恢复出厂、快照恢复建立主错误与技术详情；
- 校验所有 `confirmationText` 前后端一致。

验证：工作区筛选测试、组织关系测试、Agent 删除 Rust + Web 测试、恢复出厂测试、快照恢复测试。

### 批次 B：主流程术语

- AgentPackage → Agent 配置（默认层）；
- 管理视图/AgentPackage → 配置/原始文件；
- 页面引用 → 登记外部 Agent；
- 工作区向导的“索引/登记边界”用户化；
- 资产页的来源边与反向引用用户化。

验证：Agent 创建/详情、工作区、资产页的 Testing Library 查询与快照；Chromium 检查宽窄屏文本换行。

### 批次 C：统一错误呈现

- 按动作与结果类型建立最小显式映射；
- 原始 message、code、path 进入技术详情；
- 字段错误邻近输入并用 ARIA 关联；
- 全局 notice 不再统一使用等宽字体。

验证：失败分支、焦点顺序、`role=alert/status`、键盘展开技术详情、长路径和错误码溢出。

### 批次 D：信息层级与空态

- 记忆版本折叠协议字段；
- 快照排除清单渐进披露；
- 工作区文件/Agent/资产空态区分；
- 去除普通页面重复边界，但保留首次使用和高风险事实。

验证：真实 Chromium 亮暗主题、桌面与窄屏、键盘焦点、横向溢出、可访问名称。

## 12. 结论

Bandi 不需要一次“全站重写”，也不需要引入大型 i18n 或中央文案平台。最小且有效的方案是：保留页面附近的具体说明，复用现有展示映射，新增按结果类型组织的错误呈现，并把协议证据放入技术详情。先处理 P0/P1，再调整信息层级。

最终目标不是让文案更“漂亮”，而是让用户无需理解内部模型，也能放心完成：

> **选择 Agent → 查看配置 → 修改 → 保存 → 回到 Claude Code 使用**
