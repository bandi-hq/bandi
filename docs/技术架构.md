# 班底技术架构

> 文档版本：v1.3-draft
> 更新日期：2026-08-29
> 状态：分层记忆、治理与运行投影技术边界确认稿
> 关联文档：[《产品与页面架构》](./产品与页面架构.md)

## 1. 文档目标

本文定义 Bandi 首版的技术施工边界：

- Bandi 是现实创业公司的本地数字孪生；
- Bandi Desktop、`bandi` CLI 和 Bandi Plugin 共用 Rust Local Service；
- Local Service 是入口无关的事实、策略、投影、审计和安全操作中枢；
- Bandi Plugin 是 Claude Code 正式安装与能力载体；
- 用户始终使用自己的 Claude Code CLI，Bandi 不内嵌或隐藏托管执行；
- `attach_current` 与 `launch_new` 具有不同契约；
- 首版包含 Bandi MCP 和最小 Hooks，但不据此宣称具备可靠 Runtime Connector；
- AgentPackage、Workflow 和分层编排模型继续作为核心领域基础；
- 五类 MemorySpace、候选审核、版本写回与 MemoryProjection 构成首版记忆治理契约。

## 2. 技术原则

1. **本地优先**：源码、组织、配置、凭据引用和 Workspace 默认留在用户设备。
2. **三端一中枢**：Desktop、系统 CLI 和 Plugin 不分别保存公司事实。
3. **事实分域**：SQLite 管理结构化业务事实；AgentPackage 保存长期 Agent 配置；SourceAsset 保持外部身份；RuntimeProjection 可重建。
4. **现实公司边界**：Company 映射现实公司，不作为 Workspace 或临时会话别名。
5. **分层编排**：策略显式授予公司级、部门级、岗位级和任务级编排能力。
6. **管理与执行分离**：Bandi 管理和编译上下文，Claude Code 在用户终端执行。
7. **双模式分离**：快速接入不冒充完整启动，完整启动不混写继续或恢复旧会话。
8. **受限系统能力**：React UI 无通用 Shell 和任意文件系统权限。
9. **显式修改**：写配置必须经过草稿、Diff、校验、确认、备份和原子写入。
10. **记忆分层隔离**：MemorySpace 是领域边界，每个 Agent × Workspace 使用独立项目记忆载体，共享记忆不归个人 AgentPackage。
11. **候选先审后写**：运行、Plugin、MCP 和 Hooks 只能提交 MemoryCandidate，不能直接写正式记忆。
12. **投影保留来源**：MemoryProjection 保留作用域、owner、revision、hash、纳入原因和权限裁决，不静默覆盖冲突。
13. **证据化状态**：安装、连接、候选批准、文件写入、投影重编译、Runtime 加载和任务完成分别建模。
14. **跨平台准备**：macOS 首发，契约避免依赖 Mac 专属领域语义。

## 3. 产品形态与技术栈

### 3.1 发布形态

```text
第一阶段：macOS Bandi Desktop + Rust Local Service + bandi CLI + Bandi Plugin
第二阶段：Windows 客户端及平台适配
第三阶段：本地 Web、远程连接和可靠 Runtime 能力
```

### 3.2 技术栈

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 | 窗口、系统权限、目录选择、文件/终端唤起 |
| 前端 | React + TypeScript + Vite | 页面、交互与类型化 ViewModel |
| UI | Tailwind CSS v4 + shadcn/ui + Radix + Lucide | 语义 Token、可访问组件与图标 |
| 本地核心 | Rust | 领域服务、路径安全、配置、投影、入口、审计 |
| 数据库 | SQLite/WAL | 组织、工作流、策略、版本、接入和证据索引 |
| 本地通信 | Tauri Command / localhost 类型化 API | Desktop、CLI、Plugin 的受限接口 |
| Claude 集成 | Bandi Plugin | Skill、Agent、MCP、Hooks、settings |
| 系统入口 | `bandi` CLI | doctor、status、attach 指引和完整启动 |
| 凭据 | 系统钥匙串 | MCP 和外部服务的安全引用 |
| 实时 UI | SSE 或 Tauri Event | 本地长操作进度与可信状态更新 |

Node Sidecar 与 Claude Agent SDK 不属于首版必选路径。若后续 Runtime Connector 需要独立进程，仍必须服从 Rust 的策略与业务事实边界。

```text
┌────────────────────┐

┌─────────▼──────────┐      ┌────────────────────┐
│ Rust Local Service │◄─────┤ bandi CLI          │ 系统 Shell
│                    │      └────────────────────┘
│ Workspace Registry │
│ Organization       │      ┌──────────────────────────────────┐
│ Agent Package      │◄─────┤ Bandi Claude Code Plugin         │
│ Workflow Registry  │ MCP/ │ Skill · 董事长助理 Agent · MCP  │
│ Policy Engine      │ Hook │ Hooks · settings                 │
│ Entry Service      │      └──────────────┬───────────────────┘
│ Projection Compiler│                     │
│ Memory Service     │
│ Evidence Correlator│              用户自己的 Claude Code CLI
│ Audit & Local Ops  │
└─────────┬──────────┘
          │
          ├── SQLite / AgentPackage / SourceAsset

Runtime Connector（后续，L2）
└── correlateSession / observeExecution / collectUsage / stop / resume
```

### 4.1 Rust Local Service 边界

Local Service 是 SQLite 业务事实的唯一写入者，负责：

- Workspace、Company、Department、Role 和组织服务关系；
- AgentPackage、SourceAsset、WorkspaceBinding 和配置版本；
- WorkflowDefinition、WorkflowRun、步骤、交接、证据与审批；
- OrchestrationPolicy、委派范围、最大深度、循环检测和升级；
- 跨入口 Workspace/Company 匹配与接入策略；
- PluginInstallation、兼容性和组件完整性；
- AttachmentContext 解析；
- MemorySpace 元数据、逻辑定位、读取/提议/审核/发布权限和自审升级；
- MemoryCandidate 的校验、去重、冲突、Diff、审核和改投；
- 批准后的记忆备份、原子写入、MemoryRevision 与哈希审计；
- RuntimeProjection 与分层 MemoryProjection 的编译、校验和不可变快照；
- LaunchContext 构建与安全命令结构；
- Session 候选关联和 L0/L1 证据持久化；
- 路径授权、文件监听、Git、冲突、备份与原子发布；
- 受限打开文件、目录、编辑器与终端；
- 所有高风险操作和入口事件审计。

Local Service 不负责：

- 替董事长审批经营决策；
- 直接执行 Claude 推理；
- 把 Hook/MCP 事件推断成完整运行事实；
- 允许 Plugin 或 UI 绕过策略直接写业务数据库；
- 允许任何 Agent、MCP、Hook 或 Runtime 绕过 Memory Service 直接修改正式长期记忆。

### 4.2 客户端边界

React UI 不直接读写任意文件、拼接 Shell、读取凭据、写 SQLite 或推断 Runtime。Tauri 只暴露受限业务命令和平台适配。

`bandi` CLI 和 Plugin 只调用 Local Service 的入口无关服务，不复制 Company 匹配、编排策略、投影或启动逻辑。

## 5. Bandi Plugin

### 5.1 定位

Bandi Plugin 是 Claude Code 侧稳定安装基线，不是 AgentPackage、RuntimeProjection 或普通第三方 SourceAsset。概念结构：

```text
Bandi Plugin
├── Skill
├── 董事长助理 Agent
├── Bandi MCP
├── Hooks
├── settings
└── Plugin manifest
```

具体目录名、manifest 字段和 settings 支持范围必须按实施时目标 Claude Code 版本验证，本文不固定未经验证的格式。

### 5.2 Skill

Skill 负责：

- 识别进入 Bandi、查询组织、启动 Workflow、提交结果和请求审批等意图；
- 选择 `attach_current` 或 `launch_new` 流程；
- 通过 MCP 读取 Local Service 返回的事实与策略；
- 在意图含糊、候选冲突或涉及实际操作时确认。

Skill 不硬编码全部公司关系，也不把“小班”“班底”等词实现为绝对唤醒词。

### 5.3 董事长助理 Agent

Plugin Agent 提供 Claude Code 中稳定的运行时身份、职责、工具和默认行为。实际公司、Workspace、授权与 Workflow 由 AgentPackage 和动态上下文提供；长期记忆由授权 MemorySpace 经 MemoryProjection 提供。

```text
Plugin Agent = 稳定 Claude Code 运行外壳
AgentPackage = 长期董事长助理事实来源
RuntimeProjection = 本次完整启动的动态快照
```

### 5.4 Bandi MCP

首版候选工具：

```text
bandi.get_current_context
bandi.list_companies
bandi.list_available_workflows
bandi.start_workflow
bandi.get_current_step
bandi.delegate_step
bandi.submit_result
bandi.request_approval
bandi.report_blocker
bandi.get_handoff
bandi.attach_session
```

接口名称只是领域候选，实施时按 MCP 与 Claude Code 目标版本验证。MCP：

- 连接 Plugin 与 Local Service；
- 不定义 Workflow；
- 不控制终端；
- 不决定组织关系；
- 不以“可连接”证明工作流运行中；
- 不得绕过 Local Service 策略直接变更业务事实；
- 记忆相关能力仅可读取授权 MemoryContext、提交 MemoryCandidate 和查询审核状态，不能直接写正式记忆。

具体记忆 MCP 工具名留待目标版本验证，不在本文固化为已实现 API。

### 5.5 Hooks

首版最小 Hooks 用于：

- SessionStart / SessionEnd 的候选关联；
- UserPromptSubmit 的入口或目标审计；
- PreToolUse 的策略门禁；
- PostToolUse 的有限执行证据；
- Prompt、Tool、Session 候选和 AgentExecution 的相关性辅助。

边界：

- PreToolUse 可按宿主能力 allow、deny、ask 或调整输入，但具体契约需验证；
- PostToolUse 发生在动作后，不能撤销已执行动作；
- Hook 超时、缺失或宿主降级不能当作绝对 fail-closed 安全保证；
- Hooks 已配置不等于当前 Session 已可靠关联。

因此不可逆和高风险操作仍须在 Local Service 侧做最终校验。

### 5.6 settings

Plugin settings 只提供稳定默认值和宿主支持的配置。用户级、项目级和 WorkspaceBinding 覆盖必须可解释、可审计，不能把动态组织事实写死进 Plugin。

### 5.7 PluginInstallation

```ts
interface PluginInstallation {
  version: string
  scope: 'user' | 'project' | 'unknown'
  components: PluginComponentStatus[]
  compatibility: CompatibilityStatus
  standardCommand: CommandStatus
  optionalAlias: CommandStatus
  checkedAt: string
}
```

这只表达安装和配置（L0），不证明已在会话中调用。

## 6. 入口模型与命名

```ts
type EntryMode = 'attach_current' | 'launch_new'

type EntrySurface =
  | 'desktop'
  | 'system_cli'
  | 'plugin_skill'
  | 'slash_alias'
  | 'semantic_trigger'
```

### 6.1 命名规则

- `bandi`：系统 Shell CLI；
- `/bandi:bandi`：正式 Plugin Skill 标准命名空间入口；
- `/bandi`：可选 standalone Skill/Command 薄别名，不是 Plugin 默认承诺；
- 自然语言：非确定语义触发候选。

短别名必须处理安装作用域和命名冲突，并只转发到正式 Skill 或 Local Service，不复制上下文匹配、策略或启动实现。

### 6.2 语义触发

自然语言触发必须：

1. 识别用户是否真的希望进入 Bandi；
2. 选择或确认 EntryMode；
3. 补齐 Company、Workspace 和目标；
4. 执行同一 Local Service 策略；
5. 在写入、启动、委派或审批前确认。

它不能因为出现“小班”“bandi”“班底”而绕过任何步骤。

## 7. 双入口服务契约

```ts
interface BandiEntryService {
  inspect(input: EntryInspectionInput): Promise<EntryInspection>
  attachCurrent(input: AttachCurrentInput): Promise<AttachmentResult>
  launchNew(input: LaunchNewInput): Promise<LaunchResult>
}

interface AttachmentContextResolver {
  resolve(input: AttachCurrentInput): Promise<AttachmentContext>
  validate(context: AttachmentContext): Promise<AttachmentValidation>
}

interface RuntimeProjectionCompiler {
  compile(input: ProjectionInput): Promise<RuntimeProjection>
  validate(projection: RuntimeProjection): Promise<ProjectionValidation>
  snapshot(projection: RuntimeProjection): Promise<ProjectionSnapshot>
}

interface LaunchContextBuilder {
  resolve(input: LaunchNewInput, projection: RuntimeProjection): Promise<LaunchContext>
  validate(context: LaunchContext): Promise<LaunchValidation>
  buildCommand(context: LaunchContext): Promise<LaunchCommand>
}

interface SessionEvidenceCorrelator {
  ingest(event: RuntimeEvidenceEvent): Promise<EvidenceRecord>
  correlate(input: CorrelationInput): Promise<CorrelationResult>
  getLevel(executionId: string): Promise<EvidenceLevel>
}
```

### 7.1 inspect

入口检查返回：

- Local Service、Claude Code、Plugin 和命令状态；
- 当前 cwd（若入口可证明）；
- Workspace/Company 候选；
- 可用 EntryMode；
- 缺失参数、冲突和确认要求；
- 当前能达到的证据等级。

### 7.2 attach_current

输入至少包含：

```text
entry_surface
current_cwd
host_context（仅可证明字段）
requested_company（可空）
requested_workspace（可空）
user_confirmation
```

输出 `AttachmentResult`：

```text
AttachmentContext
+ 匹配依据和候选歧义
+ 董事长助理与 Workflow 摘要
+ 策略摘要
+ 权限过滤后的有限 MemoryContext
+ 当前会话限制
+ AgentExecution 接入记录
+ L0/L1 Evidence
```

约束：

- 不创建新 Session 或终端；
- 不完整编译新会话 RuntimeProjection；
- 不声称能改写当前系统提示、主 Agent、模型、权限和 settings；
- cwd 无匹配或多公司均匹配时必须请求选择；
- `attach_session` MCP 或 Hook 事件只能作为有限证据，除非满足 L2 Connector 契约；
- MemoryContext 只表示本次接入获准读取的有限记忆摘要，不保证当前会话已完整加载所有记忆层。

### 7.3 launch_new

输入至少包含：

```text
entry_surface
company_id
workspace_id
chairman_assistant_id
workflow_allowlist
terminal_preference
user_confirmation
```

输出 `LaunchResult`：

```text
RuntimeProjection
+ LaunchContext
+ 安全参数结构和命令预览
+ AgentExecution 启动记录
+ 终端或新会话请求结果
+ 当前 EvidenceLevel
```

约束：

- 语义固定为新董事长助理会话；
- 不与 `--continue`、`--resume` 或旧 Session 复用混写；
- 具体 Claude CLI 参数在实施时按目标版本验证；
- 终端请求成功只产生 L0 启动证据，不证明新 Session 已关联。

## 8. 领域事实与存储

### 8.1 SQLite

管理：

- Workspace、Company、Department、Role；
- AgentPackage 元数据和版本；
- WorkspaceBinding、SourceAsset 和导入追踪；
- WorkflowDefinition、WorkflowVersion、WorkflowRun、WorkflowStepRun；
- OrchestrationPolicy、Assignment、Approval、Handoff、Evidence；
- PluginInstallation；
- MemorySpace 元数据、逻辑定位、owner、steward、审核与可见策略；
- MemoryCandidate、ReviewDecision、MemoryRevision、版本、哈希和写入审计；
- AttachmentContext、MemoryProjection、RuntimeProjection 和 LaunchContext 的索引/快照元数据；
- AgentExecution、EntryMode、EntrySurface、证据等级和关联状态；
- 设置、权限授权和审计事件。

### 8.2 本地文件与 MemoryStorageResolver

AgentPackage 目录保存长期 Agent 配置，其中个人 `memory/` 只承载该 Agent 跨 Workspace 的长期记忆。每个 MemorySpace 使用独立逻辑文件载体，由版本化 `MemoryStorageResolver` 解析物理位置；外部 Claude Code 配置保持 SourceAsset 身份，除非用户明确导入。

首版固定逻辑定位，不提前锁死绝对根目录、文件名或 Markdown 格式：

```text
agent_long_term(agent_id)
agent_workspace(agent_id, workspace_id)
assistant_workspace_management(agent_id, workspace_id)
workspace_shared(workspace_id)
department_workspace(department_id, workspace_id)
```

Workspace 公共记忆不能存入助理 AgentPackage，部门项目记忆不能存入主管 AgentPackage，不同 Workspace 的 Agent 项目记忆不能解析到同一逻辑文件。

RuntimeProjection 保存可重建快照或引用，不成为长期配置或记忆的第二主源：

```text
Bandi Plugin 安装基线
+ Plugin Agent
+ AgentPackage / WorkspaceBinding
+ 权限过滤、版本化的 MemoryProjection
+ 允许的 Skill / MCP
+ Hooks / settings 覆盖
+ Workflow / Policy / 初始上下文
+ 版本、哈希与来源
= RuntimeProjection
```

### 8.3 凭据

Token、API Key 和账号密钥只保存于系统钥匙串、Claude Code 受管位置或用户授权 Secret Manager。SQLite 只保存安全引用、授权状态和验证时间。

### 8.4 Memory Service 与权限

Memory Service 提供领域级能力：

```text
resolveReadableSpaces
buildMemoryProjection
proposeCandidate
reviewCandidate
publishApprovedCandidate
```

以上是职责名称，不是已冻结的公开 API。Workflow 权限不能隐式替代记忆权限；读取、提议、审核和发布分别裁决。

默认读取规则：

| 身份 | 默认可读记忆 |
| --- | --- |
| 董事长助理 | 自身长期、Agent × Workspace 项目、项目管理、Workspace 公共；部门记忆按协调授权 |
| 部门主管 | 自身长期、Agent × Workspace 项目、Workspace 公共、本部门当前 Workspace 项目记忆 |
| 专业/执行 Agent | 自身长期、Agent × Workspace 项目、Workspace 公共、所属部门当前 Workspace 项目记忆 |

跨部门参与不自动授予全部部门记忆。提议者不能批准自己的候选；需要自审时按组织关系向上升级。候选改投其他 MemorySpace 后必须重新检查可见性、提议权限和审核策略。

### 8.5 记忆候选状态机

```text
Proposed → Validated → PendingReview
→ Approved | Rejected | ChangesRequested
→ WritePrepared → AtomicallyWritten → RevisionRecorded
```

- 每个 MemoryCandidate 只有一个主要目标 MemorySpace；
- `Approved` 只表示审核通过，不表示文件写入成功；
- `AtomicallyWritten` 只表示批准内容已写入目标文件，不表示投影已更新；
- `RevisionRecorded` 记录不可变版本、来源、审核、基线和哈希；
- RuntimeProjection 需要重新编译，Runtime 是否加载仍需单独证据。

写入前必须重新校验目标 revision、content hash、权限、路径和符号链接边界，并展示 Diff、创建备份后原子替换。

## 9. Workflow 与策略服务

```ts
interface WorkflowService {
  createDefinition(input: WorkflowDefinitionInput): Promise<WorkflowDefinition>
  validateDefinition(id: string): Promise<WorkflowValidation>
  publishVersion(id: string): Promise<WorkflowVersion>
  compose(parentId: string, childId: string, nodeId: string): Promise<void>
  createRun(input: CreateWorkflowRunInput): Promise<WorkflowRun>
}

interface OrchestrationPolicyService {
  evaluateStart(input: WorkflowStartRequest): Promise<PolicyDecision>
  evaluateDelegation(input: DelegationRequest): Promise<PolicyDecision>
  evaluateApproval(input: ApprovalRequest): Promise<PolicyDecision>
  detectCycle(input: DelegationGraph): Promise<CycleDetection>
}
```

策略至少检查 Agent 职责、组织关系、Workflow 作用域、委派对象、深度、Workspace、工具权限、职责分离、审批和升级条件。董事长助理不是唯一编排者。

MCP 只是这些服务面向 Claude Code 的适配层。Workflow 定义仍由 Local Service 管理。

## 10. RuntimeProjection 与 AgentExecution

### 10.1 投影语义

一次完整启动或委派解析产生不可变快照；输入版本未变时多个执行可引用同一快照。快速接入可只有 AttachmentContext 和有限 MemoryContext，不强制产生完整投影。

完整启动按 Agent、Workspace、Department、Workflow 和权限解析 MemoryProjection：

```text
Agent 长期记忆
→ Workspace 公共记忆
→ 当前 Department × Workspace 部门项目记忆
→ 董事长助理项目管理记忆（仅董事长助理）
→ Agent × Workspace 项目记忆
→ Workflow / Handoff / 临时上下文
```

每层保存 `scope`、`owner`、`revision`、`content_hash`、来源、纳入原因和权限裁决。组合顺序表示上下文逐步收窄，不是后层静默覆盖前层；内容冲突必须保留来源并阻止或显式降级投影。

### 10.2 AgentExecution

候选字段：

```text
id
entry_mode
entry_surface
attachment_context_id（可空）
launch_context_id（可空）
workflow_run_id（可空）
workflow_step_id（可空）
agent_package_id
workspace_binding_id
runtime_projection_hash（可空）
parent_execution_id（可空）
delegation_depth
session_correlation_status
evidence_level
created_at
terminal_request_result（可空）
user_marked_ended_at（可空）
```

`attach_current` 的 AgentExecution 是接入上下文记录，不表示新进程。`launch_new` 的记录是新会话启动上下文，也不自动进入运行中。

## 11. 证据等级与状态投影

```ts
type EvidenceLevel = 'L0_CONFIG' | 'L1_EVENT' | 'L2_RUNTIME'
```

### L0：配置事实

来源：文件、数据库、安装检查、投影和系统请求结果。

允许：

```text
Plugin 已安装
MCP 已配置
Hooks 已配置
AttachmentContext 已确认
MemoryCandidate 已批准
记忆文件已原子写入
MemoryRevision 已记录
RuntimeProjection 已生成
命令已生成/复制
终端已请求打开
```

### L1：有限事件证据

来源：可验证的 MCP 调用或 Hook 事件。

允许：

```text
MCP 已调用
Hook 最近触发
步骤结果已提交
Session 候选已发现
事件与 AgentExecution 有限关联
```

不得仅凭 L1 展示稳定“Session 已关联”或连续“执行中”。

### L2：可靠 Runtime Connector

要求：

- 稳定 Session 标识；
- 事件相关性、顺序与去重；
- 重连和失败恢复；
- 证据持久化；
- 能力探测和版本兼容；
- 明确停止、恢复和 Usage 来源。

只有 L2 可支持：

```text
Session 已可靠关联
执行中 / 步骤完成 / 失败
精确 Usage
可靠停止或恢复
```

UI 状态由证据投影，不由期望、终端窗口或 MCP 配置推断。

## 12. 外部 CLI 与终端安全

### 12.1 `bandi` 系统 CLI

首版职责候选：

```text
bandi                 交互式检查并选择进入方式
bandi status          查看 Local Service 与 Plugin 状态
bandi doctor          诊断 CLI、Plugin、MCP、Hooks 和权限
bandi launch          完整启动新董事长助理会话
```

命令名称与参数在实现时验证。本质要求是调用同一 BandiEntryService，而不是复制业务逻辑。

### 12.2 终端启动安全

- 使用参数数组，不拼接未验证 Shell 字符串；
- 路径规范化并限制在授权根；
- 命令预览与实际参数语义一致；
- 不展开密钥；
- 自定义终端模板单独校验；
- 用户可复制 cwd 与命令作为降级；
- 新会话命令不混入继续/恢复旧会话语义；
- `TerminalLaunchResult` 只表示系统请求结果。

## 13. 配置发布与路径安全

### 13.1 发布状态机

```text
Discovered → Parsed → Mapped → ConfigDraft → ImpactAnalyzed
→ Validated → PublishApproved → BackedUp → AtomicallyWritten
→ Rediscovered → FileUpdated
```

记忆写回单独使用 MemoryCandidate 状态机，不与普通配置发布状态混写。`RuntimeLoadVerified` 需要实际 Runtime 证据，不能作为文件发布、记忆候选获批或 MemoryRevision 记录的自然下一步。

### 13.2 安全要求

所有本地操作只能作用于用户授权 Workspace、Claude 配置根和 Bandi 数据目录。必须防止路径穿越、符号链接逃逸、命令注入、跨 Workspace 越权和静默覆盖。

高风险写操作必须显示目标、Diff、影响、可逆性和备份，并在写入前重新校验策略与基线哈希。

## 18. 技术验收标准

1. Desktop、CLI 和 Plugin 读取同一 Local Service 事实与策略；
2. Rust 是 SQLite 业务事实唯一写入者；
3. React UI 无通用 Shell 和任意文件系统权限；
4. Company 明确映射现实公司，不与 Workspace 混用；
5. Bandi Plugin、第三方 Plugin SourceAsset、Plugin Agent、AgentPackage 和 RuntimeProjection 分离；
6. `/bandi:bandi` 是标准入口，`/bandi` 只作为可选 standalone 薄别名；
7. 自然语言触发不能绕过参数、策略和确认；
8. `attach_current` 不新建 Session、不打开终端、不声称完整重建配置；
9. `launch_new` 编译完整投影并保持新会话语义；
10. 启动命令采用安全参数结构，具体参数按目标版本验证；
11. MCP 不定义 Workflow、不决定组织关系；
12. Hooks 不作为唯一安全边界或可靠 Runtime 证明；
13. L0/L1/L2 状态严格分级；
14. 主管与获授权专业 Agent 可在策略范围内编排；
15. 配置发布具有 Diff、确认、备份、原子写入和冲突保护；
16. 终端失败提供 cwd、命令和手动步骤；
17. 无 L2 Connector 时不展示可靠 Session、执行、完成和精确 Usage；
18. 五类 MemorySpace 的 owner、steward、reviewer 和 Local Service 写入执行者严格分离；
19. 每个 Agent × Workspace 使用独立项目记忆载体，共享与部门记忆不存入个人 AgentPackage；
20. Workflow 权限不自动授予记忆读取、提议、审核或发布权限；
21. 任何运行组件都不能直接写正式记忆，提议者不能自审；
22. MemoryCandidate 批准、原子写入、Revision 记录、投影重编译和 Runtime 加载分别建模；
23. MemoryProjection 保留来源、版本、哈希、纳入原因和权限裁决，冲突不静默覆盖；
24. 960×640 下可完成 Workspace、公司、Agent、记忆审核、集成检查和双入口流程。
