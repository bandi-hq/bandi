# 班底前端界面改造执行方案

> 文档版本：v0.1
>
> 文档状态：待执行

> 关联文档：[AI 组织操作系统产品设计文档](./AI组织操作系统-产品设计文档.md)、[班底技术实现简要方案](./班底-技术实现简要方案.md)

## 1. 文档目的

本文用于指导班底现有 React Web UI 的整体改造，覆盖：

- shadcn/ui 的引入和本地化管理；
- shadcn/ui 官方 Skill 的项目级配置；
- 设计 Token、公共组件和业务组合组件的边界；
- 桌面工作区布局和各页面的信息架构；
- 从现有全局 CSS 到新组件体系的渐进迁移；
- Web 与 Tauri 桌面端的共同验收；
- 许可证、依赖、CSP、测试和上游更新边界。

本次改造属于**表现层重建**，不是业务重写。现有领域模型、API、Fake 数据源、SSE、路由和治理语义继续作为事实契约。

## 2. 已确认的实施方向

### 2.1 总体决定

采用以下方案：

```text
React 19 + TypeScript + Vite
        ↓
Tailwind CSS v4
        ↓
shadcn/ui CLI 分发的本地组件源码
        ↓
Radix primitives + Lucide 图标
        ↓
班底自己的主题 Token、组合组件和页面布局
        ↓
同一套 UI 同时用于浏览器 Web 和 Tauri 客户端
```

Hermes Studio 只作为视觉和交互参考，不作为依赖、Fork 基座或组件源码来源。

### 2.2 对“提前把组件下载到本地”的准确理解

该思路总体正确。shadcn/ui 不是传统的黑盒运行时组件包，而是通过 CLI 将组件源码和所需依赖加入当前项目。加入后的文件位于仓库内，可直接审查、修改、测试和版本控制。

不过，“全部提前下载”在本方案中定义为：

> **一次性加入本轮页面改造需要的全部第一方公共组件，而不是无差别执行 `shadcn add --all`。**

官方 CLI 确实支持：

```bash
pnpm dlx shadcn@4.19.0 add --all --cwd apps/web
```

但默认不执行该命令，原因是：

- 会加入当前产品没有使用的源码和依赖；
- 增加审查、测试和未来上游同步成本；
- 容易把示例能力误认为班底已经提供的产品能力；
- 与项目“简洁优先、只解决当前问题”的原则不一致。

本轮采用“批准清单一次性落地”的方式，批准清单见第 7 节。后续需要新组件时继续使用同一 CLI 添加，仍然属于本地公共组件。

### 2.3 公共组件放置位置

本轮公共 UI 源码放在：

```text
apps/web/src/components/ui/
```

暂不创建 `packages/ui`，原因是：

- 浏览器版和 Tauri 客户端当前复用同一个 `apps/web` 构建产物；
- 桌面端不是第二套独立 React 应用；
- 现在抽成 workspace package 不会产生真实复用，只会增加构建和发布边界。

未来出现第二个独立前端消费者后，再将稳定组件提取到 `packages/ui`。

## 3. 参考边界与许可证

### 3.1 Hermes Studio

本次参考的是：

```text
https://github.com/EKKOLearnAI/hermes-studio
```

截至 2026-08-29，该仓库采用 BSL-1.1：

- 允许个人、教育、研究等非商业用途；
- 商业使用需要单独许可证；
- 计划于 2029-05-10 转换为 Apache-2.0。

因此本项目只参考以下抽象特征：

- 紧凑桌面工作区；
- 稳定的左侧导航；
- 扁平面板和行式信息；
- 对话式任务入口；
- 主工作区与上下文信息的层级关系；
- 审批、执行状态和工具信息的呈现方式。

不得直接复制：

- Vue 组件源码；
- SCSS、CSS 数值和类名体系；
- 图标、图片、动画和品牌资产；
- 页面文案；
- Crew、Session、Profile、Terminal 等领域对象；
- Hermes Studio 的数据库、状态模型或 Runtime 逻辑。

现有技术文档中的其他 Hermes 固定基线，不构成对 EKKOLearnAI/hermes-studio 当前源码的复用授权。

### 3.3 Registry 限制

本轮只允许使用官方 `@shadcn` Registry。

任何社区 Registry、Block 或远程 URL 在加入前必须单独确认：

- 仓库和固定版本；
- 许可证；
- 被加入的具体文件；
- 运行时依赖；
- 网络、存储、文件或浏览器权限；
- 是否包含远程字体、图片、脚本或追踪代码；
- 是否符合 Tauri CSP。

不得因为 shadcn CLI 能下载某个 Registry 项目，就默认其已经通过班底的依赖和许可证审查。

## 4. 不变的业务边界

以下文件原则上不因本次 UI 改造而修改：

```text
apps/web/src/domain/model.ts
apps/web/src/app/AppData.tsx
apps/web/src/api/client.ts
apps/web/src/api/fake.ts
apps/web/src/api/sse.ts
apps/web/src/data/bootstrap.ts
apps/web/src/lib/format.ts
```

以下路由保持不变：

```text
/
/assets
/tasks
/tasks/:taskId
/approvals
/experience
/reconciliation
```

以下业务语义必须保持：

1. 目标先形成提案，用户确认后才创建任务；
2. Runtime 离线时不能伪装成任务已启动；
3. 资产“发现、解析、加载、调用”四个阶段不可互换；
4. Unknown 和 Reconciliation 不能显示为成功；
5. 审批只绑定精确动作，不提供“全部允许”；
6. 批准后进入待消费状态，不等于动作已执行；
7. ExperienceCandidate 只影响未来候选，不反向改写本次事实；
8. 对账只展示服务端声明的 `safeActions`；
9. 外部副作用不明确时禁止自动重放；
10. Token 和成本估算必须保留来源标记。

页面可重组 DOM 和视觉层级，但不能通过“简化界面”隐藏上述事实。

## 5. 工程接入方案

### 5.1 配置范围

shadcn 配置属于 `apps/web`，目标文件结构为：

```text
apps/web/
├── components.json
├── package.json
├── vite.config.ts
├── tsconfig.json
└── src/
    ├── components/
    │   ├── ui/                 # shadcn CLI 加入并由项目维护的源码
    │   ├── workspace/          # 班底无业务状态的组合组件
    │   └── ...
    ├── features/               # 业务组件和页面
    ├── lib/
    │   └── utils.ts            # cn() 等公共工具
    └── styles.css              # Tailwind/shadcn 主题入口
```

### 5.2 初始化选择

初始化时固定以下选择：

| 配置 | 选择 | 原因 |
| --- | --- | --- |
| Framework | Vite + React + TypeScript | 保持现有技术栈 |
| Primitive base | Radix | 无障碍成熟，适合 Dialog、Sheet、Tooltip、Menu 等工作区交互 |
| Style | New York / 对应当前 CLI 的紧凑预设 | 作为基础，不直接决定最终品牌视觉 |
| Tailwind | v4 | 使用当前 Vite 官方接入 |
| CSS variables | 开启 | 建立语义 Token 和暗/亮主题扩展能力 |
| Base color | Neutral 或 Zinc | 作为中性基础，业务状态色由班底定义 |
| Icons | Lucide | 复用现有图标依赖和视觉语言 |
| RSC | 关闭 | 当前为 Vite SPA |
| TypeScript | 开启 | 保持严格类型 |
| RTL | 关闭 | 当前以中文界面为主，暂不扩大范围 |

`components.json` 由 CLI 生成后再审查和提交，不手工猜测当前 Schema。至少应包含：

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/styles.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "iconLibrary": "lucide",
  "aliases": {
    "components": "@/components",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks",
    "utils": "@/lib/utils"
  },
  "registries": {}
}
```

若 CLI 当前版本生成的字段与示例不同，以 CLI Schema 和 `shadcn info --json` 为准，但上述技术选择不变。

### 5.3 路径别名

当前项目还没有 `@/*`。实施时同时修改：

- `apps/web/tsconfig.json`：加入 `@/* -> ./src/*`；
- `apps/web/vite.config.ts`：加入相同的 Vite alias；
- `apps/web/components.json`：配置相同 aliases。

三处必须一致，不能只让编辑器或只让 Vite 单独解析成功。

### 5.4 Tailwind 与现有 CSS 共存

当前 `apps/web/src/styles.css` 超过 4200 行，不能在初始化时直接覆盖。

迁移策略：

```text
现有 styles.css
→ 原样移动为 styles/legacy.css
→ 新 styles.css 作为 Tailwind v4 + shadcn 主题入口
→ 未迁移页面继续使用 legacy class
→ 每完成一个页面，删除对应 legacy 样式
→ 所有页面迁移后删除 legacy.css
```

执行要求：

- 移动前先读取并保存完整文件；
- 不使用 CLI 强制覆盖现有 CSS；
- 初始化后逐段比较 theme/reset 影响；
- 新页面不继续引用旧页面 class；
- 旧页面迁移完成前不得一次性删除旧 CSS；
- 不通过把字号继续缩小来制造“紧凑感”。

Tailwind Preflight 可能改变未迁移页面的默认元素样式，接入后必须立即检查所有路由。如果共存影响过大，先隔离 Preflight，再在 Shell 和表单迁移完成后启用。

### 5.5 版本固定

仓库当前依赖采用精确版本。本次同样遵守：

- 执行文档中的首次初始化使用 `shadcn@4.19.0`；
- CLI 加入到 manifest 的依赖保留精确版本；
- 不在提交中使用 `^` 或 `~` 放宽版本；
- 后续升级单独执行并审查 diff。

若正式实施日期距离本文较远，可先重新核验最新版本，再明确更新本文基线，不能悄悄以 `@latest` 生成不可复现结果。

## 6. shadcn/ui Skill 配置

### 6.1 Skill 的作用

官方 Skill 用于给 Claude Code 等开发助手提供项目感知上下文。它会：

- 发现项目中的 `components.json`；
- 运行 `shadcn info --json`；
- 读取 framework、Tailwind 版本、aliases、base、icon library 和已安装组件；
- 指导使用正确的组件 API、组合模式和语义 Token；
- 提供 CLI、主题、Registry 和 MCP 的参考。

Skill **不会**：

- 替代 `shadcn init`；
- 自动把全部组件加入项目；
- 替代代码审查；
- 自动保证 Registry 许可证和安全性；
- 成为班底 Runtime 的执行 Skill。

### 6.2 安装方式

官方命令是：

```bash
npx skills add shadcn/ui
```

本项目使用 pnpm，实际执行时使用对应 package runner，并安装为**项目级 Claude Code Skill**，不安装为全局 Skill：

```bash
pnpm dlx skills@1.5.23 add shadcn/ui --agent claude-code --copy -y
```

执行后必须读取并审查新增的 Skill 文件、链接和 lock 元数据，再决定提交哪些文件。

### 6.3 Node 版本注意事项

截至 2026-08-29：

- 班底项目固定 Node `>=20.20.0 <21`；
- `skills@1.5.23` 声明需要 Node `>=22.20.0`。

因此不能把 `skills` CLI 加入班底 Web 的运行依赖，也不能为了安装 Skill 直接修改整个项目的 Node 基线。

正确做法：

1. 在临时 Node 22.20+ shell 中运行一次项目级 Skill 安装命令；
2. 审查生成文件；
3. 回到项目规定的 Node 20.20 环境开发和运行应用；
4. Skill 本身只作为开发辅助文本，不进入 Web/Tauri 构建产物。

如果当前机器没有安全的临时 Node 22 环境，则先记录为待办，不使用不受支持的 Node 20 强行执行安装。

### 6.4 Skill 存放边界

shadcn Skill 属于**开发助手配置**，不得放入：

```text
runtime-assets/skills/
```

`runtime-assets/skills` 是班底产品 Runtime 的受控执行资产。把开发用 shadcn Skill 放进去，会错误地把“帮助开发班底前端”变成“班底对用户任务可调用的能力”。

### 6.5 使用规则

安装 Skill 后，后续所有 shadcn 组件工作遵循：

1. 先运行 `shadcn info --json` 确认项目上下文；
2. 先检查本地是否已有组件；
3. 使用 `shadcn docs/search/view` 获取当前版本文档；
4. 加入前执行 `--dry-run`；
5. 更新本地已修改组件前执行 `--diff`；
6. 不未经审查使用 `--overwrite`；
7. Registry 必须明确，不默认猜测社区来源；
8. 加入后读取全部新增文件；
9. 保持语义 Token，不在页面散落原始颜色；
10. Skill 建议不得覆盖班底的领域、安全和许可证边界。

## 8. 组件分层

### 8.1 第一层：`components/ui`

职责：

- CLI 加入的基础源码；
- 交互、ARIA、variants 和基础样式；
- 不认识班底领域对象；
- 不调用 `useAppData()`；
- 不写业务文案。

示例：

```text
Button
Badge
Sheet
Dialog
Table
Progress
Sidebar
```

### 8.2 第二层：`components/workspace`

职责：

- 班底自己的无业务状态组合组件；
- 统一桌面工作区布局；
- 可以组合多个 shadcn primitives；
- 通过 props 接收内容，不直接执行业务动作。

建议组件：

```text
WorkspaceShell
WorkspaceHeader
WorkspacePanel
SectionHeader
MetricStrip
FilterToolbar
StatusSummary
DataTableFrame
EmptyState
ProgressWithLabel
DecisionList
ActivityList
```

不要把每个 `div` 都组件化。只有跨页面重复、具有布局或无障碍契约的结构才进入这一层。

### 8.3 第三层：Feature 组件

职责：

- 认识具体领域类型；
- 组织业务信息；
- mutation 通过页面传入 callback；
- 不直接绕过 `AppData` 请求 API。

建议拆分：

```text
features/workbench/ProposalSheet.tsx
features/tasks/TaskTimeline.tsx
features/tasks/TaskEvidence.tsx
features/approvals/ApprovalCard.tsx
features/experience/ExperienceCard.tsx
features/reconciliation/ReconciliationCard.tsx
```

### 8.4 第四层：页面

页面负责：

- 调用 `useAppData()`；
- 页面级过滤和派生数据；
- 业务 action 和导航；
- 组合 Feature 与 Workspace 组件；
- 页面标题和主要 landmark。

## 9. 设计语言

### 9.1 视觉原则

1. 工作区优先，不再以“统计卡片墙”为主视觉；
2. 行式信息优先，减少彼此孤立的大卡片；
3. 交办目标是工作台第一视觉层级；
4. 正在执行的任务是第二层级；
5. 待用户决策的事项必须醒目但不淹没主工作区；
6. 资产、成本和技术证据按任务上下文呈现；
7. 状态使用文字、图标和颜色三重表达；
8. 紧凑通过间距和结构实现，不继续缩小辅助文字；
9. 默认暗色，但 Token 结构同时支持未来亮色；
10. 不使用远程字体、CDN 图片或外部脚本。

### 9.2 Token 方向

用 shadcn 语义 Token 替代当前并行的两套命名：

| 新 Token | 当前含义 |
| --- | --- |
| `background` | 页面背景 |
| `foreground` | 主文本 |
| `card` / `card-foreground` | 工作区面板 |
| `popover` | 浮层 |
| `muted` / `muted-foreground` | 次级区域和文本 |
| `border` / `input` | 分隔与输入边界 |
| `primary` | 主要动作 |
| `secondary` | 次要动作 |
| `accent` | hover/选中 |
| `destructive` | 危险和失败 |
| 班底扩展 `success` | 已验证成功 |
| 班底扩展 `warning` | 待处理、未知、风险 |
| 班底扩展资产阶段 Token | discovered/parsed/loaded/invoked |

迁移后页面不得继续散落原始 `#hex` 或临时 `rgba()`。数据可视化色与交互语义色分开。

### 9.3 密度与尺寸

建议基础值：

```text
顶栏：44–48px
展开侧栏：216–232px
折叠侧栏：56–64px
普通控件：34–38px
触控目标：窄屏不小于 44px
基础圆角：6–8px
面板间距：12–16px
内容间距：4 / 6 / 8 / 12 / 16 / 24
正文：不低于 13px
辅助文字：不低于 11–12px
```

最终数值由实际页面验证确定，不直接复制 Hermes Studio。

## 13. 上游组件维护

shadcn 组件源码加入后属于班底仓库中的本地维护代码。更新策略：


禁止默认执行：

